# 전사 끝 경계 실패 재현과 복구

실행일: 2026-09-05. 기준 커밋 `877e2d5` 이후 이 문서와 함께 추가한 작업 트리에서 수정했다. [계획](../plans/2026-09-05-transcription-end-review-plan.md), [실제 진단 원시값](results/2026-09-05-transcription-end-diagnostic.json), [두 앱 결과](results/2026-09-05-transcription-end-ui.json)를 연결한다. 새 빌드의 전체 긴 영상 성능은 별도 재측정 대상이다.

## 관측한 실패

기존 60분 Chrome 전사는 추론 후 `전사 시각이 원본 길이와 일치하지 않습니다.`로 실패했다. 이전 성공 10분 결과 6회와 실패 로그를 `test-output/transcription-performance-initial-failure/`에 보존했다.

입력의 디코딩된 WAV는 16kHz·57,600,000표본, 정확히 3,600초였다. 동일한 실제 Whisper small/whisper.cpp 1.9.3-dev CLI 설정으로 다시 추론해 원시 JSON을 보존했다. 총 580개 중 마지막 하나가 **3,596.240~3,600.240초**, 즉 원본보다 240ms 늦은 끝 시각을 반환했다. 이전 변환기는 100ms를 넘는 초과를 거부해 정상 구간까지 전사 결과로 가져오지 못했다.

고정 엔진의 [음성 특징 패딩과 타임스탬프 생성 소스](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/src/whisper.cpp), [CLI JSON 시각 출력](https://github.com/ggml-org/whisper.cpp/blob/371b5a7561823ab2bb32142d2751e35e7534727b/examples/cli/cli.cpp)을 확인했다. 30초 창과 패딩을 쓰며 예측 시각이 원본 끝과 항상 일치하는 것은 아니다. 실제 초과량은 소스에서 추정하지 않고 보존한 원시 JSON에서 측정했다.

## 수정한 동작

전사 엔진 출력에서 원본 안에 시작하고 마지막 30초 안에 걸친 구간만 끝 조정을 허용한다. 원본 초과량과 원래 구간 길이 모두 30초 이하여야 한다. 원본 밖에서 시작하는 구간, 큰 시각 오류, 역전·겹침·손상된 자료는 계속 거부한다. 일반 프로젝트/출력의 `0 ≤ 시작 < 끝 ≤ 원본 길이` 검증은 유지한다.

실제 원시 출력 580개의 문구·시작 시각을 모두 보존했고 마지막 끝만 3,600초로 맞췄다. 원래 모델 끝 3,600.240초를 `timingWarning`에 남긴다. 문구를 알아서 줄이거나 검토 완료로 처리하지 않는다.

자막 목록과 편집 창은 **영상 끝 검토 필요**를 표시한다. **다음 검토 자막으로 이동**으로 해당 문구와 원본 청취 위치로 이동한다. 원본 청취용 VTT는 검토 전에도 범위 안의 시각으로 표시한다. 이 경로는 출력용 SRT와 분리되어 있다.

문구와 끝 시각을 확인해 명시적으로 완료하기 전에는 해당 자막의 SRT·자막 포함 미리보기/MP4를 거부한다. 문구를 수동 또는 AI로 바꾸거나 컷이 경계를 바꾸면 검토가 다시 필요하다. 해당 자막을 컷에서 완전히 제외하면 출력하지 않는다. 검토와 그 취소/다시 실행은 기존 자막 이력을 따른다.

프로젝트 v7에 경고와 검토 키를 보존한다. v1~v6을 열 수 있고 기존 컷 검토 키와 v6 용어는 유지된다. 구버전 앱이 새 경고를 버린 채 출력하지 않도록 새 파일 버전을 사용한다.

## 측정 도구 보완

긴 전사 도구는 기존 결과 파일이 있으면 앱 실행 전에 거부한다. 같은 출력 폴더로 중복 호출해 파일이 바뀌지 않는 것을 확인했다. 실패한 실행도 경과 시간·진행 단계·RSS 표본/최대값·오류를 별도로 저장하도록 보완했다. 앞으로의 전사 기록에는 검토가 필요한 끝 경계 수를 포함한다.
