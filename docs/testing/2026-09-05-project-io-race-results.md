## 재현한 문제와 수정

두 앱에서 프로젝트 A의 읽기를 대기시킨 뒤 B를 열었지만 A가 늦게 완료되면 B를 덮어썼다. 파일을 읽는 동안 새로 편집한 경우에도 이후 편집이 사라지고 미저장 표시가 지워졌다. A의 임계값은 -60, B는 -50, 이후 편집은 -42로 구분해 관측했다.

Mac에서는 임계값 -41로 저장을 시작하고 -42로 편집하면, 파일에는 요청 당시 -41이 올바르게 저장되지만 늦은 완료가 화면의 미저장 표시를 지웠다. 다른 프로젝트로 바꾼 뒤 편집해도 같은 문제가 발생했다. 최신 편집이 실제로 디스크에 저장된 것처럼 오해하고 창을 닫을 수 있는 상태였다.

이제 파일 선택의 순서, 열린 프로젝트, 적용한 편집 변경을 식별한다. 오래된 읽기 완료·오류는 새 선택에 적용하지 않는다. 읽는 동안 편집이 바뀌면 이를 보존하고 프로젝트를 다시 선택하도록 안내한다. 원본 선택·샘플 불러오기에도 작업 순서를 적용했다.

Mac 저장은 요청 당시 프로젝트와 편집 버전을 완료 시점에 비교한다. 그 사이 수정이 있으면 미저장 표시를 유지하고 아직 저장되지 않은 변경을 안내한다. 프로젝트가 바뀌면 이전 프로젝트의 저장 완료임을 표시한다. 저장 중 버튼과 단축키의 중복 요청을 막으며 창 닫기 보호에도 진행 중인 저장을 반영한다. 취소·실패 후 저장 상태를 정리해 다시 저장할 수 있게 한다.

## 범위와 재실행

읽기는 생성 파일의 실제 `File.text()` 반환을 늦췄고, 오류 조건 하나는 제어된 예외를 주입했다. Mac 저장은 실제 IPC·직렬화·파일 작성·fsync·rename을 사용하면서 rename 직전에 대기시켰다. 실제 OS 교체 확인 창, 취소한 분석과 새 원본의 전체 경합 조합, 브라우저 다운로드 관리자의 디스크 완료는 별도 범위다. E06 전체의 완료로 표시하지 않는다.

앞서 완료한 긴 전사 성능은 `1e927ff` 앱의 측정값으로 유지한다. 이 I/O 수정 후에는 위 실제 전사·미디어 회귀를 실행했으며 긴 성능 측정 전체를 새 앱의 결과로 소급하지 않는다.

```sh
npm run test:project:io -- --output=test-output/새-시험-이름
```

기존 결과 폴더를 덮어쓰지 않는다. 입력과 결과는 생성 영상·임시 프로젝트로 한정하고 사용자 원본은 사용하지 않는다.
