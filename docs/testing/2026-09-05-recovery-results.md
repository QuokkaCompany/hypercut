# HyperCut 복구·부분 복원·앱 성능 검증 — 2026-09-05

> 이후 추가한 선택 범위의 컷 경계 미리보기와 갱신된 테스트 수는 [범위 미리보기 결과](2026-09-05-range-preview-results.md)에 기록했다.

## 현재 판정

데스크톱·브라우저 편집 프리뷰의 장애 복구와 UI 검증을 보강했다. **정식 MVP 전체 통과는 아직 아니다.** 실제 한국어 평가 자료와 사람의 경계 청취·편집 시간 비교, 실제 AI 연결 검증은 실행하지 않았다. 앞선 [프리뷰 결과](2026-09-05-preview-results.md)의 측정값은 당시 기록으로 유지하며, 변경된 상태는 이 문서를 따른다.

## 변경과 검증

- 작업 생성 응답을 기다리는 순간에도 취소할 수 있다. 클라이언트가 작업 ID를 먼저 정하고, 서버는 먼저 도착한 취소를 기록한다. 취소 응답은 실행 중인 자식 작업이 정리된 뒤 반환한다. 늦게 도착한 결과가 기존 편집을 바꾸지 않는다.
- 전부 무음인 영상에서 필요한 시간 범위만 복원할 수 있다. 입력 범위 바깥쪽 프레임까지 보존하며 100ms보다 짧게 남는 제거 조각도 복원한다. 전체가 제거된 경우 빈 출력의 차단 이유를 표시한다.
- 컷을 선택한 뒤 R로 복원/제거하고, 버튼에 초점이 있어도 Cmd/Ctrl+Z로 되돌릴 수 있다. 타임라인 확대·축소와 수평 스크롤을 추가했다. 확대 시 시간 눈금과 기존 파형 데이터의 표시 밀도를 함께 조절한다.
- 네이티브 프로젝트·MP4 저장은 별도 임시 파일을 완성하고 fsync한 뒤 교체한다. 기존 파일은 쓰기 실패나 교체 전 프로세스 종료에도 유지된다.
- 50ms보다 짧다는 이유로 유효한 한 프레임 영상을 출력하지 못하던 제한을 제거했다.

## 오류를 실제로 재현한 범위

**공간 부족:** 임시 32MiB HFS+ sparse 디스크 이미지만 마운트해 공간을 채웠다. 프로젝트 교체와 실제 미디어 출력에서 ENOSPC를 받았다. 기존 프로젝트와 원본 해시가 유지됐고, 실패한 임시 출력이 정리됐으며, 시험용 파일을 비운 뒤 재시도가 성공했다. 시험 종료 후 볼륨을 분리하고 디스크 이미지를 삭제했다. 사용자 저장 장치를 채운 시험이 아니다.

**권한과 프로세스 종료:** 시험용 디렉터리의 쓰기 권한을 제거해 EACCES/EPERM를, 시험용 원본의 읽기 권한을 제거해 읽기 거부를 확인했다. 실제 FFmpeg 자식 프로세스를 출력 도중 SIGKILL한 뒤 원본 보존·작업 파일 정리·재시도를 검사했다. 저장은 제품과 같은 원자적 쓰기 함수를 별도 프로세스에서 실행하고 최종 교체 직전에 종료했다. Electron 앱 전체를 저장 도중 강제 종료한 수동 시험이나 전원 차단 내구성 시험은 아니다.

**취소 경합:** 브라우저에서 분석 POST가 서버에 도착하기 전에 보류하고 취소했다. 약 53.19ms 뒤 UI가 종료 상태가 됐고, 기존 복원 편집이 유지됐다. 다른 설정으로 새 분석을 완료한 뒤 과거 요청을 해제해도 새 결과를 덮어쓰지 않았다. 손상 프로젝트 열기도 기존 편집을 보존했다.

**AI 실패:** 모의 OpenAI 응답을 지연시킨 뒤 창을 닫고 설정을 바꾸었다. 과거 제안은 적용되지 않았다. 모의 503 이후에도 로컬 분석·출력이 완료됐다. 실제 공급자 호출·인증·과금은 수행하지 않았다.

**부분 복원:** 4초짜리 실제 무음 MP4에서 전체 제거 상태를 만든 뒤 [1.01, 1.99)초를 복원했다. 결과는 [1, 2)초를 보존했고, 1초 미리보기·MP4 전체 디코딩을 통과했다. 실행 취소/다시 실행, R 복원, 역전 범위 차단, 전체 복원도 확인했다.

## 전체 앱 성능

Apple M4 Max / Mac16,9 / 14 CPU / 36GiB / macOS Darwin 25.5.0 / arm64 / 로컬 SSD. Node 24.14.1, Electron 44.2.0, FFmpeg·ffprobe 8.1.1. AC 전원, 저전력 모드 꺼짐을 확인했다. 다른 앱을 종료하거나 OS 캐시를 강제로 비우지는 않았다.

자료는 단순한 화면·플래시·사인파로 만든 1080p30 H.264/AAC 48kHz 합성 영상이다. 실제 촬영 영상보다 인코딩이 쉽다. 분석 시간은 네이티브 파일 선택 버튼 클릭부터 입력 검사·해시·화면 준비·파형·최종 컷 생성까지 포함한다. 출력 시간은 전체 디코딩 검증과 저장 버튼 표시까지다. 사용자 지정 경로로 마지막 복사하는 시간은 포함하지 않았다.

RSS는 Electron 루트와 모든 자손 프로세스를 250ms마다 합산했다. 테스트 드라이버는 제외했다. 샘플 사이의 순간 피크는 포착하지 못할 수 있다. 첫 실행은 ‘OS 캐시 상태 불명’, 이후 실행은 캐시가 있는 실행으로 기록했다. 성능 시험 중 다른 미디어 시험은 실행하지 않았고, 작은 소스 편집·빌드는 있었다. 이 패키지의 측정 이후 부분 복원·확대 UI를 추가했으므로 최종 UI 변경을 포함한 전체 RSS를 새로 측정했다는 뜻은 아니다.

브라우저 60분·1,000컷 상태에서 복원/실행 취소 32회, 설정 16회, 재생/정지 16회, 합계 64회 조작 p95는 **150.35ms**였다. 설정·재생/정지에는 Playwright locator 처리 시간도 포함하며 모든 표본은 두 번의 화면 갱신까지 측정했다. 분석·렌더 미리보기·내보내기 취소의 표시 지연은 각각 **20.0 / 21.9 / 29.9ms**, 종료 상태까지 **224.6 / 313.3 / 321.6ms**였다. 1,000개 컷과 재분석 가능 상태가 유지됐다.

스트레스 시험에서 1배 축척의 작은 컷 클릭 영역이 겹쳐 선택이 실패했다. 확대를 추가하고 32배에서 401번째 컷 선택을 확인했다. 이 측정 후 눈금 표시 밀도·파형 메모화를 조정했고, 마지막 짧은 E2E에서 확대 시 서로 다른 시간 눈금 5개가 보이고 선택 컷으로 스크롤되는 것을 확인했다. UI 성능 원시값을 마지막 눈금 변경 후의 재측정으로 간주하지 않는다.
