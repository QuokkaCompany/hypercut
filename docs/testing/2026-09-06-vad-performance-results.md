# 긴 영상 말소리 보호 성능 — 브라우저 메모리 목표 미충족

2026-09-05 밤에 시작해 2026-09-06 America/New_York에 완료했다. 앱 `0ffdf1a`에서 **10분·60분 × Chrome/Mac × 각 3회, 총 12회**를 마쳤다. 분석·출력 시간, 조작 반응과 취소·재시도는 측정 목표를 충족했다. **브라우저 합산 RSS는 6회 모두 2GiB를 초과했으므로 VAD 성능 게이트는 실패**다. Mac의 6회는 측정 목표를 충족했다. 실제 한국어 품질이나 G3 전체 완료를 뜻하지 않는다.

[실행 계획](../plans/2026-09-05-vad-performance-plan.md), [12회 원시 결과](results/2026-09-06-vad-performance-before.json), [RSS 피크·원시 기록 무결성 검사](results/2026-09-06-vad-performance-resource-audit.json), [60초 시험 도구 점검](results/2026-09-06-vad-performance-smoke.json)을 연결한다. 제품의 성능 목표를 완화하지 않았다. `status: completed`는 모든 측정을 끝냈다는 뜻이고, `measuredGoalsPass: false`와 종료 코드 1이 성능 실패를 나타낸다.

| 앱 / 자료 | 횟수 | 전체 분석 중앙값 / 최대 | 출력·검증 중앙값 / 최대 | 합산 RSS 최대 | 조작 묶음별 p95 중 최대 |

분석은 파일 선택 직전부터 브라우저 업로드 또는 네이티브 파일 검사·해시·영상 준비·프레임 시간표·음량 분석·실제 VAD·최종 컷 표시까지 포함한다. 초기 목표인 입력 길이의 20% 이내를 모두 충족했다. 출력은 버튼 클릭부터 실제 MP4의 전체 디코딩 검증과 저장 버튼 표시까지다. 마지막 사용자 지정 경로로 복사하는 시간은 포함하지 않는다. 입력 길이 이내 목표를 모두 충족했다. 미디어 작업 3회로 p95를 계산하지 않았다.

각 실행마다 복원/실행 취소 32회, 설정 변경 32회, 재생/정지 32회를 측정했다. 합계 **1,152회**이며 각 묶음의 p95를 별도로 계산했다. Playwright 호출 직전부터 기대 상태 확인과 2회 화면 갱신까지의 시간이라 자동화 오버헤드도 포함한다. 복원 상태·설정 재분석 표시·실제 영상의 재생/정지 상태를 확인했다. 이 수치를 분석 도중의 전체 UI 응답이나 모든 조작으로 확대하지 않는다.

## 메모리 실패와 다음 수정

Chrome 10분 3회의 피크는 2.013·2.053·2.066GiB, 60분은 2.191·2.227·2.282GiB였다. 모두 출력 단계에서 최고치를 기록했다. 첫 Chrome 10분 피크 시 FFmpeg는 약 681MiB, 첫 60분 피크 시 약 715MiB였으며 브라우저·서버의 메모리도 함께 합산됐다. 이는 측정된 동시 점유의 근거이며 FFmpeg 하나만 원인이라고 확정한 결과가 아니다.

현재 출력 경로는 FFmpeg의 H.264 인코더 스레드 수를 자동 선택에 맡긴다. 다음 수정에서는 인코더 동시 처리 수를 제한하는 후보를 실제 비교해 메모리를 낮추고, 속도·출력 길이·싱크·자막·효과음을 다시 검증한다. 이 기록 시점에는 최적화를 적용하지 않았다. 최적화 전 수치를 삭제하거나 통과 수치로 바꾸지 않는다.

## 취소·재시도·데이터

첫 측정 후 실제 VAD 진행 중 취소하고 전체 프로젝트를 다시 저장해, 저장 시각을 제외한 모든 필드가 직전 저장 내용과 같은지 비교했다. 다음 두 번째 측정의 완료를 취소 후 재시도 완료 근거로 삼았다.

| 조건 | 취소 문구 DOM 갱신 | 취소 후 UI 재시도 가능 | 서버 상태·프로젝트 보존·재시도 완료 |
| --- | --- | --- | --- |
| Chrome / 10분 | 1.2ms | 208.1ms | PASS |
| Mac / 10분 | 1.3ms | 301.9ms | PASS |
| Chrome / 60분 | 2.4ms | 209.3ms | PASS |
| Mac / 60분 | 2.3ms | 206.4ms | PASS |

문구 갱신은 실제 클릭부터 MutationObserver가 확인한 DOM 변화까지다. 실제 화면에 픽셀이 그려진 시각을 직접 측정한 값으로 표현하지 않는다. 재시도 가능 시간에는 자동화 호출 오버헤드가 포함됐다. 서버가 `cancelled` 상태가 된 것, 분석 버튼 활성화, 두 번째 분석·출력 완료를 확인했다. 문구 300ms·재시도 5초 목표를 해당 측정 범위에서 충족했다.

10분은 매번 39개 컷, 60분은 233개 컷으로 반복 결과가 일치했다. 디코딩한 표본 수, VAD 모델명, 구간 순서·원본 범위, 컷에 따른 예상 출력 길이와 실제 전체 디코딩 완료를 확인했다. 생성 영상의 SHA-256이 보존됐고 페이지 오류·관측한 외부 브라우저 요청·RSS 표본 오류는 0건이었다. 이는 OS 전체 네트워크 차단 증거가 아니다.

## 환경과 판정 한계

- Apple M4 Max, 14 CPU, 36GiB RAM, macOS Darwin 25.5 arm64, 전원 어댑터 연결. 사용자 앱은 종료하지 않았다.
- Node 24.14.1, FFmpeg 8.1.1, ONNX Runtime 1.29.0, 고정 SHA-256의 Silero VAD 6.2.1, CPU 추론의 intra/inter 스레드 각 1개. 앱·모델·시험 코드·의존성 잠금 파일·Mac 패키지 해시를 기록하고 종료 후 현재 파일과 대조했다.
- 1080p30 H.264/AAC 48kHz, 단순 화면과 반복한 한국어 Eddy TTS다. 음량을 0.006배로 줄여 -40dBFS보다 낮은 입력을 만들었다. 음량 분석만으로 전체가 후보가 되고 VAD로 유지 구간이 생기는 실제 경로를 확인했다. 유지 구간이 생겼다는 사실을 발음 보존의 독립 정답이나 실제 녹음 품질로 세지 않는다.
- Chrome+별도 로컬 서버 또는 Mac 앱과 각각의 모든 자손 PID를 합산했다. 시험 드라이버는 제외했다. 합산 RSS는 프로세스 간 공유 페이지가 중복 포함될 수 있어 고유 물리 메모리 사용량과 다르다.
- RSS 표본 주기는 250ms이며 이번 원시 기록의 가장 큰 표본 간격은 약 281ms였다. 표본 사이의 순간 피크는 놓칠 수 있다. 분석·조작·출력 각 단계의 원시 기록과 최대 표본을 보존했다.
- 첫 실행은 새 앱 프로세스, 이후 두 실행은 같은 앱이다. OS 캐시를 비우지 않아 첫 실행도 cold-cache가 아니다. 시험 중 다른 미디어 시험이나 빌드는 실행하지 않았다.

원시 분석·프로젝트·RSS 파일은 로컬 `test-output/vad-performance-current/`에 보존했다. 저장소의 원시 결과와 피크 감사 파일에 대응 파일명과 RSS 파일 해시를 남겼다. 60초 두 앱 점검은 같은 앱·모델·시험 코드로 수행했지만 12회 성능 수치에 합산하지 않았다.

현재 앱의 1,000컷 임계값 단독 조건, 긴 영상의 자막·효과음 동시 합성, OS cold-cache, 실제 한국어 녹음의 발음·CER·복원 부담·시간 절감은 남아 있다. 앞선 [전사 성능](2026-09-05-transcription-performance-results.md)의 4GiB 목표와 이번 VAD 무음 편집의 2GiB 목표를 혼합하지 않는다. 이 기록으로 P01/P02·S01~S07·G3 전체를 통과 처리하지 않는다.

```sh
node scripts/vad-benchmark.mjs --output=test-output/새-시험-이름
```

기본 실행은 10분·60분 × 두 앱 × 3회와 조건별 취소·재시도다. `--durations=60 --iterations=1`은 두 앱의 짧은 도구 점검이며 취소는 생략한다. `--surfaces=browser` 또는 `--surfaces=desktop`으로 제한할 수 있다. 기존 결과 폴더를 덮어쓰지 않는다.
