# 출력 메모리 개선 — VAD 성능 12회 재측정 통과

2026-09-06 America/New_York. H.264 인코더의 동시 처리 수를 제한한 뒤 **10분·60분 × Chrome/Mac × 각 3회, 총 12회와 취소·재시도 4조건**이 측정 기준을 충족했다. 브라우저 합산 RSS 최대는 2.282GiB에서 **1.977GiB**, Mac은 1.656GiB에서 **1.397GiB**로 감소했다. 출력 시간은 증가했다. 아래 수치는 합성 입력과 해당 환경에서 측정한 결과이며, 실제 영상 품질·cold-cache·G3 전체 완료를 뜻하지 않는다.

[개선 계획](../plans/2026-09-06-render-memory-plan.md), [수정 전 12회](2026-09-06-vad-performance-results.md), [60분 Chrome 3회](results/2026-09-06-render-memory-browser-long.json), [10분 두 앱 6회](results/2026-09-06-render-memory-ten-minute.json), [60분 Mac 3회](results/2026-09-06-render-memory-mac-long.json), [무결성·데이터·RSS 감사](results/2026-09-06-render-memory-audit.json)를 연결한다. 가장 부담이 컸던 60분 브라우저부터 실행하고 나머지 조건을 순차 실행했다. 세 기록의 앱·모델·시험 코드·패키지 해시가 같은 것을 확인했다.

## 변경과 비용

`server/media.mjs`에서 출력 인코더 스레드 수를 `Math.min(4, availableParallelism())`로 정하고 FFmpeg의 출력 영상에 `-threads:v`로 전달한다. 이 기계에서는 4개다. 원본 해상도, 코덱, CRF, 인코딩 프리셋, 컷·자막·효과음 계산은 유지했다. 인코딩 비트스트림의 바이트 동일성이나 모든 실제 영상의 지각 화질 동일성을 주장하지 않는다.

| 조건 | 수정 전 RSS 최대 | 수정 후 RSS 최대 | 수정 전 출력 중앙값 | 수정 후 출력 중앙값 / 최대 |
| --- | --- | --- | --- | --- |
| Chrome / 10분 | 2.066GiB | **1.795GiB** | 16.236초 | 24.666 / 24.675초 |
| Mac / 10분 | 1.520GiB | **1.205GiB** | 16.417초 | 24.939 / 24.955초 |
| Chrome / 60분 | 2.282GiB | **1.977GiB** | 95.466초 | 146.740 / 146.960초 |
| Mac / 60분 | 1.656GiB | **1.397GiB** | 96.903초 | 147.372 / 147.377초 |

각 행은 수정 전·후 각각 3회다. 출력은 버튼 클릭부터 전체 디코딩 검증과 저장 버튼 표시까지이며 마지막 사용자 경로 복사는 포함하지 않는다. 모든 실행이 입력 길이 이내 목표를 충족했다. 메모리를 줄이는 대신 이 합성 자료의 출력·검증 시간이 약 51~54% 증가했다. 3회 결과로 p95를 계산하지 않았다.

첫 60분 브라우저 실행의 출력 피크에서 FFmpeg 점유는 약 715MiB에서 404MiB로 줄었다. 브라우저·서버 메모리도 총합에 포함됐다. 프로세스별 실제 최대 표본과 원시 파일 해시를 감사 JSON에 남겼다. 특정 실행의 FFmpeg 수치 하나를 전체 앱의 고유 물리 메모리나 모든 입력에 대한 상한으로 표현하지 않는다.

## 분석·조작·취소

| 조건 | 전체 분석 중앙값 / 최대 | 조작 묶음별 p95 중 최대 | 취소 후 재시도 가능 |
| --- | --- | --- | --- |
| Chrome / 10분 | 8.349 / 8.813초 | 68.1ms | 210.0ms |
| Mac / 10분 | 8.735 / 8.791초 | 40.3ms | 209.1ms |
| Chrome / 60분 | 48.583 / 48.930초 | 67.8ms | 206.0ms |
| Mac / 60분 | 49.598 / 49.652초 | 59.4ms | 277.5ms |

분석은 파일 선택부터 업로드/파일 검사·해시·프레임 시간표·음량/VAD·최종 컷 표시까지 포함하며 입력 길이의 20% 이내였다. 각 실행에서 복원/실행 취소 32회, 설정 변경 32회, 재생/정지 32회, 총 1,152회 조작을 측정했다. 자동화 호출 오버헤드와 기대 상태 확인·2회 화면 갱신이 포함된 각 묶음의 p95는 200ms 이내였다. 분석이나 출력 도중의 모든 UI 응답을 측정한 결과는 아니다.

취소는 실제 VAD 진행 중 수행했다. 문구 DOM 갱신은 1.3~2.5ms였고 서버의 `cancelled` 상태, 분석 버튼 활성화, 저장한 전체 프로젝트 보존을 확인했다. 두 번째 측정의 완료가 취소 후 재시도 완료 근거다. DOM 갱신 시각은 픽셀 표시 시각을 직접 관측한 값과 구분한다.

## 정확성·회귀 근거

- **12회 모두 수정 전 분석 JSON의 전체 필드와 동일했다.** 컷 개수뿐 아니라 경계·파형·음량 후보·VAD 구간을 비교했다. 10분은 39개 컷, 60분은 233개 컷이었다.
- 수정 전·후의 저장 프로젝트도 저장 시각을 제외한 모든 필드가 동일했다. 원본 파일 해시, 예상 출력 길이와 전체 디코딩 완료를 확인했다.
- 모든 실행에서 페이지 오류·관측한 외부 브라우저 요청·RSS 표본 오류는 0건이었다. OS 전체 네트워크 차단 시험은 아니다.
- 단위 테스트 **75 PASS**. 실제 미디어 통합 검사 **28 PASS**: CFR/VFR·PTS 오프셋·선택 트랙·한 프레임/부분 출력·독립 플래시/음성 표식·자막 3종/회전/SAR/프레임 위치·효과음 PCM/음량/배치·실패 후 복구를 검사했다.
- 일반 편집·전사/자막·효과음의 Chrome/Mac UI **6회 PASS**. 실제 저장·출력·디코딩과 원본 보호를 확인했다. 전사는 생성한 한국어 TTS와 로컬 Whisper를 사용했으며 인증된 LLM 호출은 수행하지 않았다.
- 타입 검사·브라우저 빌드·Mac 패키징 PASS. [통합/UI 회귀 기록](results/2026-09-06-render-memory-regressions.json)을 연결한다.

먼저 실행한 [10분 브라우저 1회 예비 측정](results/2026-09-06-render-memory-probe.json)은 후보의 메모리 감소 확인용이며 위 12회에 합산하지 않았다. 이 예비 실행도 같은 앱·패키지·시험 코드였으나 단일 실행만으로 반복 성능 통과를 선언하지 않았다.

## 재현 범위와 남은 항목

같은 Apple M4 Max 14 CPU·36GiB·Darwin 25.5 arm64·전원 어댑터, Node 24.14.1·FFmpeg 8.1.1·고정 Silero 모델과 합성 1080p30 H.264/AAC 48kHz 자료를 사용했다. 첫 실행은 새 앱이고 이후 두 실행은 같은 앱이다. OS 캐시를 비우지 않았으며 다른 미디어 시험이나 빌드를 동시에 실행하지 않았다.

RSS는 앱과 모든 자식 PID의 합을 250ms마다 측정하고 드라이버를 제외했다. 최대 표본 간격은 약 280ms였다. 공유 페이지가 중복 합산될 수 있고 표본 사이의 순간 피크는 놓칠 수 있다. 측정 당시 HEAD는 `7b08c8e`였고 인코더 변경은 작업 트리에 있었다. 정확한 런타임 기준은 각 기록의 소스·패키지 SHA-256이다. 기록한 해시 중 수정 전과 달라진 것은 `server/media.mjs`와 Mac 패키지였으며 나머지 모델·시험 코드·입력 관련 값은 일치했다.

원시 RSS·분석·프로젝트 파일은 `test-output/render-memory-browser-long/`, `test-output/render-memory-ten-minute/`, `test-output/render-memory-mac-long/`에 보존했다. 세 실행 모두 종료 코드 0으로 끝났다. 같은 조건 전체를 다시 실행하려면 다음 명령을 사용한다.

```sh
node scripts/vad-benchmark.mjs --output=test-output/새-시험-이름
```

이 수정으로 앞선 VAD 측정의 브라우저 메모리 실패를 해당 조건에서 해소했다. 최신 앱의 1,000컷 임계값 단독 측정, 긴 영상 자막·효과음 동시 합성, OS cold-cache, 실제 한국어 영상의 발음·CER·작업 시간, Mac OS 오프라인 및 인증된 AI 연결 검증은 남아 있다. 기존 실패 기록과 미실행 항목을 통과로 바꾸지 않는다.
