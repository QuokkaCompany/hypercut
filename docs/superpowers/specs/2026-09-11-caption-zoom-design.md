# 발화 강조 자막과 부드러운 줌

상태: 방향 승인됨, 상세 설계 검토용. 구현 및 검증 실행 전.

## 목표와 범위

한국어 설명 영상을 무음 편집한 뒤, 중요한 문장에 강조 자막과 줌을 적용해 완성도를 높인다. 첫 버전은 기존 영상과 전사문을 사용하며 문장 전체를 강조한다. 단어별 타이밍 추정, 피사체 자동 추적, 9:16 변환, 제목 카드, 범용 모션 편집기는 후속 범위다.

성공 조건은 효과 개수가 아니라 읽기 쉬운 결과, 발화와 맞는 타이밍, 적은 수정 횟수다. HyperFrames보다 낫다는 판단은 동일 입력을 사용한 실측 이후에만 한다. 현재 비교 근거는 https://github.com/heygen-com/hyperframes 의 공개 기능과 현재 HyperCut 코드이며 경쟁 제품 실행 벤치마크는 없다.

## 사용자 흐름

1. 영상을 불러오고 무음 편집 및 전사문 교정을 마친다.
2. 자막 목록에서 문장을 선택하고 ‘강조 추가’를 누른다. AI 없이도 같은 기능을 사용할 수 있다.
3. 강조 자막과 줌을 각각 켜고 끌 수 있다. 기본 줌은 중앙 1.08배, 범위는 1.00–1.15배다. 사용자가 정규화된 초점 좌표를 조절할 수 있다.
4. ‘중요한 부분 제안’을 요청하면 선택한 AI 연결로 문장 ID, 원문, 원본 시간 범위와 지시문을 보낸다. 원본 미디어는 첨부하지 않는다. 최대 20문장/4,000자 단위로 요청하고 자동 다음 배치 호출은 하지 않는다.
5. 제안 목록은 원문, 선정 이유, 자막/줌 설정을 보여준다. 선택 적용, 개별 제외, 실행 취소를 제공한다. AI는 원문을 다시 쓰거나 자막 시간을 생성하지 않는다.
6. 구간 인코딩 미리보기로 효과를 확인한 뒤 전체 MP4를 출력한다. 빠른 탐색 화면에는 효과가 포함되는지 명시하고, 최종 확인은 실제 렌더 경로를 사용한다.

## 데이터와 시간 규칙

프로젝트 v9에 `visualAccents` 배열을 추가한다. 항목은 ID, cueId, 원본 start/end, 원문 및 출력 언어 스냅샷, captionEnabled, zoomEnabled, zoomScale, focusX/focusY를 가진다. 원문 스냅샷은 문자열 비교를 위한 값이며 별도 미디어를 저장하지 않는다. v1–v8 입력은 빈 배열로 올린다. 알 수 없는 신규 버전을 이전 버전으로 저장하지 않는다.

시간은 원본 기준 반개구간 [start, end)으로 보관한다. 렌더 시 기존 kept 구간과 교차해 출력 프레임으로 변환한다. 완전히 잘린 문장은 효과를 출력하지 않으며 컷 복원 시 다시 나타난다. 부분 삭제된 문장은 남은 각 연속 구간에서 효과를 적용하고 각 구간마다 진입/퇴장을 계산한다. 동일 문장의 중복 강조는 하나로 병합하고 서로 다른 문장의 효과 구간 중첩은 명시적 오류로 거부한다.

전사 교체, 문장 삭제, 텍스트/시간/출력 언어 변경으로 스냅샷이 달라지면 해당 항목은 검토 필요 상태가 된다. 사용자가 현재 문장으로 다시 연결하거나 제거하기 전에는 그 항목이 포함되는 효과 출력을 막는다. 단순 컷 변경은 원본 기준으로 다시 매핑한다. 요청 이후 프로젝트·전사·컷·강조 상태가 바뀌면 오래된 AI 제안을 적용할 수 없다.

## 표현과 렌더링

강조 자막은 기존 하단/상단 자막을 대체하며 같은 문장을 이중 표시하지 않는다. 첫 버전은 기존 Noto 글꼴, 굵은 글씨, 고대비 배경과 고정된 강조색을 사용한다. 기존 3줄 제한 및 글리프 검사를 유지한다. 자막 포함이 꺼져 있으면 강조 자막도 출력하지 않지만 줌은 독립적으로 동작한다. SRT/TXT는 원문과 시간만 유지한다.

줌은 영상 레이어에만 적용하고 자막은 최종 출력 크기에 합성한다. 해상도·프레임 수·오디오 길이를 변경하지 않는다. 연속 효과 구간 길이를 D라 할 때 진입과 퇴장은 각각 min(0.25초, D/2), 보간은 smoothstep을 사용한다. 중앙 유지 구간에서는 목표 배율을 유지한다. 한 프레임 이하 구간에서는 줌을 생략한다. 초점은 크롭이 영상 밖으로 나가지 않도록 제한한다.

별도 Go 모듈이 프레임별 배율·크롭 위치를 결정하고 `internal/media/export.go`가 기존 영상 필터와 자막 합성 사이에 연결한다. FFmpeg 필터는 이 규칙을 보존하는지 작은 좌표 격자 영상으로 먼저 검증한다. 미리보기와 최종 출력은 같은 매핑 및 합성 함수를 사용한다. 렌더 캐시 키와 출력 무효화 의존성에 강조 상태를 포함한다.

## 연결 지점과 작업 순서

1. 계약: `src/types.ts`, 새 `shared/visual-accents.mjs`, 새 Go 강조 검증/매핑 모듈. 독립적인 고정 예상값으로 JS/Go 계약을 맞춘다.
2. 저장: `shared/timeline.mjs`의 프로젝트 처리와 `internal/media/project.go`, 로컬/클라우드 프로젝트 경로에 v9와 검증을 연결한다.
3. 렌더: Go export/render 경로에 줌과 강조 자막을 연결한다. 실제 FFmpeg 출력으로 매핑·크롭·자막 합성 순서를 검증한다.
4. UI: 기존 자막 목록과 분리된 강조 편집 컴포넌트를 연결한다. `src/App.tsx`는 상태·프로젝트 I/O·작업 스냅샷만 연결한다. 한 번의 제안 적용은 한 번의 실행 취소 단위다.
5. AI: 기존 제안 검토 패턴과 provider 라우팅을 재사용해 강조 제안 계약을 추가한다. 잘못된 cueId·범위·배율·중복은 서버에서 거부한다.
6. 브라우저 및 데스크톱 저장/재열기, 취소/재시도, 클라우드 직렬화까지 확인한다.

구현 상세 계획은 이 설계를 검토한 뒤 작성한다. 설치된 스킬 경로에서 `writing-plans/SKILL.md`를 찾지 못했으므로 해당 스킬을 사용했다고 기록하지 않는다.

## 검증 기준

모든 항목의 현재 상태는 NOT_RUN이다. 문서 작성은 통과 근거가 아니다.

| 검사 | 독립 확인 방법 | 통과 조건 |
| --- | --- | --- |
| 컷 이후 타이밍 | 프레임 번호가 찍힌 합성 영상과 수동 계산한 출력 구간 | 시작/끝 오차 1프레임 이내, 삭제 구간 효과 없음 |
| 줌 | 좌표 격자 원본의 기준점 위치를 출력 프레임에서 측정 | 목표 위치/배율 오차 2픽셀 이내, 검은 여백 없음 |
| 자막 | 긴 한글·숫자·영문 혼합 문장을 실제 출력 프레임으로 확인 | 이중 표시·잘림·글리프 누락 없음 |
| 미리보기 일치 | 같은 원본 시간의 미리보기/최종 출력 프레임 비교 | 배율·위치·문구·효과 경계 동일, 인코딩 색상 오차는 별도 허용 |
| 복구와 저장 | 적용→취소→다시 실행→저장→재열기 및 지연된 응답 | 이전/현재 상태 정확히 복구, 오래된 제안 적용 없음 |
| 호환성 | 기존 v1–v8 fixture와 신규 v9 왕복 | 기존 편집 보존, 강조 값 손실 없음 |
| 음성 보존 | 동일 컷의 기존 출력과 개선 출력의 PCM·길이·동기 표식 | 오디오 변화 없음, A/V 오차 1프레임 이내 |
| 렌더 실패 | 취소·잘못된 설정·미지원 글리프·재시도 | 부분 결과를 완료로 표시하지 않음, 재시도 가능 |

제품 비교에는 합성 영상과 별도로 한국어 설명 녹화본 3개를 사용한다. 각 60–120초, 같은 전사문·컷·강조 문장을 고정하고 HyperCut 수동 적용, HyperCut AI 제안, HyperFrames 작업을 비교한다. 작업 순서를 번갈아 배치하고 활성 편집 시간, 렌더 대기 시간, 수정 횟수, 타이밍 오류, 가독성 평가를 각각 기록한다. AI 품질 평가는 실제 선택 provider 호출을 수행했을 때만 집계한다. 입력 영상이 없으면 실제 녹화 비교는 BLOCKED로 남긴다.

초기 목표는 동일 품질을 만족하는 수동 HyperCut 대비 활성 편집 시간 중앙값 30% 감소와 타이밍·저장 손실 오류 0건이다. 세 영상의 결과는 탐색적 결과로 보고 일반적인 경쟁 우위로 확대하지 않는다. 성능은 효과 없는 동일 컷 출력과 비교해 시간·메모리를 기록하고, 렌더 시간 2배 또는 최대 메모리 1.5배 초과 시 최적화 검토 후 출시 판단한다.
