# 로컬 모델 다운로드 취소·복구 검증

2026-09-06. 전사 계획 T05의 모델 다운로드 중 취소·설치 복구가 아직 미검증이다. 현재 준비 스크립트는 고정 해시·최대 크기·임시 파일·rename을 사용하지만 SIGINT/SIGTERM을 취소 신호로 처리하지 않는다. 기본 프로세스 종료에서는 비동기 `finally` 정리가 완료된다고 보장할 수 없으므로 실제 자식 프로세스로 재현한다.

## 변경과 범위

- 기존 다운로드 함수를 별도 검증 가능한 모듈로 옮긴다. 고정 SHA-256·최대 바이트·새 임시 파일·검증 후 원자적 파일 교체를 유지한다.
- 다운로드와 기존 파일 해시 확인에 AbortSignal을 전달한다. 다운로드 동안만 SIGINT/SIGTERM을 취소로 연결하고, 파일·응답 스트림 정리 뒤 종료하도록 한다. 준비 스크립트는 취소 메시지와 130/143 종료 코드를 사용한다.
- 검증된 기존 파일은 요청 없이 재사용한다. HTTP 오류·연결 중단·크기 초과·해시 불일치·취소에서는 기존 파일을 보존하고 이번 작업의 임시 파일만 제거한다. 검증 완료 전에는 설치 완료로 표시하지 않는다.
- 파일 교체의 완료 지점은 해시 확인 뒤의 성공한 rename이다. 그 뒤 도착한 취소는 이미 검증·교체된 파일을 되돌리지 않고 남은 준비 작업을 중단한다. 다음 실행에서 해시를 다시 확인해 재사용한다. 이 경우를 교체 전 취소의 기존 파일 보존과 구분한다.
- 강제 SIGKILL에서 비동기 정리가 실행됐다고 주장하지 않는다. 남은 불완전 파일이 정식 모델 경로로 사용되지 않고, 다음 요청이 새 임시 파일에서 검증 후 완료되는지 확인한다. 다른 실행의 임시 파일을 찾아 삭제하지 않는다.
- 범위는 다운로드 수명주기다. CMake 빌드 도중 프로세스 트리 취소, 다른 Mac의 새 설치, 실제 외부 모델 서버의 모든 장애를 이 시험으로 통과 처리하지 않는다. 현재 설치된 모델·엔진·앱 패키지는 변경하지 않는다.

## 검증 방법

원래 설치 스크립트를 먼저 보존한다. 해당 다운로드 함수의 수정 전·후 실행을 각각 자식 프로세스에서 비교한다. 외부 모델 대신 작은 합성 바이트를 반환하는 로컬 HTTP 서버와 시험 전용 임시 폴더를 사용한다. 서버가 실제 바이트를 전송하고 자식이 임시 파일에 쓴 것을 확인한 뒤 SIGINT 또는 SIGTERM을 보낸다.

확인할 사례는 정상 다운로드·해시 재사용(외부 요청 0회), 잘못된 해시, 크기 초과, HTTP 오류, 끊긴 응답, 이미 취소된 요청, 쓰기 중 SIGINT/SIGTERM 및 정리 후 성공 재시도다. SIGKILL 뒤 재시도도 별도 사례로 기록한다. 각 단계에서 기존 파일 해시, 실제 종료 코드/신호, 임시 파일 목록·크기, 서버 요청/연결 종료를 기록한다.

현재 장시간 미디어 검증이 끝난 뒤 테스트를 실행한다. 실제 앱의 추론 모델과 런타임, 전역 도구, 계정 인증은 사용하지 않는다. 통과한 다운로드 사례는 T05의 해당 조건에만 연결하고 실제 전사·설치 전체의 완료로 확대하지 않는다.
