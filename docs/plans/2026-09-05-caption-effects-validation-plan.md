# HyperCut 전사·자막·효과음 검증 및 테스트 계획

작성일: 2026-09-05. 상태: 일부 구현·검증 진행. 로컬 전사·문구/시각 수정·SRT·v3 저장은 [전사 결과 기록](../testing/2026-09-05-transcription-results.md), 후속 디자인·v4 저장·MP4 합성은 [합성 결과 기록](../testing/2026-09-05-caption-rendering-results.md)에 구분했다. 실제 녹음 품질·긴 영상의 자막 성능, AI 교정·효과음은 미실행이다.

이 문서는 [무음 편집 검증 계획](2026-09-05-validation-plan.md)과 [MVP 테스트 계획](2026-09-05-test-plan.md)의 후속 범위다. 기존 MVP 39개, AI 8개, VAD 7개 사례와 별도로 전사 7개·자막 10개·효과음 5개를 정의한다. 기존 자동 테스트 통과 수를 아래 기능의 통과 증거로 사용하지 않는다.

## 1. 요구사항과 완료 조건

| 사용자 요구 | 확인할 결과 | 관련 사례 |
| --- | --- | --- |
| 음성 인식으로 편집을 돕는다 | 선택한 트랙을 로컬에서 전사하고, 원본 발화 시각과 연결해 검토할 수 있음 | T01~T07 |
| 자막 오타를 수정한다 | 직접 수정 및 선택한 AI의 교정 제안을 비교·적용·되돌릴 수 있음 | C03, C07~C08 |
| 자막 디자인을 적용한다 | 미리보기와 실제 영상 파일에 같은 스타일·문자·시각이 반영됨 | C05~C06, C10 |
| 효과음을 수정한다 | 시각·길이·음량을 조절하고 컷 변경·저장·실제 출력에도 유지됨 | FX01~FX05 |
| 사용하는 AI를 선택한다 | 선택한 연결만 사용하고, 실패해도 기존 편집 및 로컬 기능을 사용할 수 있음 | C08, FX04, 기존 A01~A08 |

우선순위는 무음 편집 품질 → 로컬 전사 → 자막 수정·스타일·출력 → AI 교정 → 효과음이다. 전사 결과가 틀렸다는 이유로 원본 발화를 자동 삭제하지 않는다. 음량 임계값, VAD 음성 점수, STT 문장·시각은 서로 다른 데이터로 보관하고 검증한다.

## 2. 구현 전에 고정할 계약

### 로컬 전사

- 원본 파일 식별자, 선택 트랙·채널, 언어, 엔진·모델 버전과 전사 구간을 함께 기록한다. 텍스트와 시각은 수정 가능하며 전사를 다시 실행해 기존 수정을 덮어쓸 때는 새 결과를 검토하거나 되돌릴 수 있어야 한다.
- 전사 원문은 원본 시간축으로 저장한다. 재인코딩한 편집 영상의 시각을 원본 시각으로 잘못 저장하지 않는다.
- 채널 평균으로 반대 위상의 발화를 없애지 않는다. 첫 버전은 전사할 채널을 명시적으로 고르도록 하고 단일 채널은 자동 선택한다. 다채널 자동 결합은 별도 검증 전 지원 완료로 표시하지 않는다.
- 모델 파일을 준비하는 단계와 준비된 모델로 추론하는 단계를 구분한다. 다운로드가 필요하면 대상·용량·진행·취소를 표시하고, 완료 후 오프라인에서 사용할 수 있어야 한다. 다운로드 중단 파일을 설치 완료로 처리하지 않는다.
- 모델 없음·손상·지원하지 않는 실행 환경은 구별 가능한 오류다. 로컬 전사가 실패했다고 클라우드 전사를 자동 호출하지 않는다.

### 컷과 자막 시간축

자막 구간은 반열린 원본 구간 `[start, end)`으로 저장한다. 출력 시 최종 유지 구간과 교차한 범위만 편집 시간축으로 옮긴다. 컷을 복원하면 원본 시각에서 다시 계산하며 변환된 시각에 중복으로 차감하지 않는다.

독립 고정 정답 예시:

| 최종 유지 구간 | 원본 자막 구간 | 기대 결과 |
| --- | --- | --- |
| `[0,2), [4,8), [9,12)` | `[5,6.2)` | 출력 `[3,4.2)` |
| 같음 | `[2.5,3.5)` | 완전히 삭제된 자막은 출력하지 않음. 프로젝트에는 원본 구간 보존 |
| 같음 | `[1.5,4.5)` | 유지되는 시각 조각은 `[1.5,2), [2,2.5)`. 문구의 단어 위치 근거가 없으면 경계 검토 필요 |

문장 하나가 삭제 구간을 가로지르면 원문 전체를 여러 조각에 복제하지 않는다. 단어 시각이 검증된 경우에만 해당 단어를 자동 배치한다. 근거가 부족한 경우 사용자가 문구·시각을 정리할 수 있도록 표시하고, 해결 전에는 자막 포함 출력을 완료하지 않는다. 자막을 끈 영상 출력은 가능하다. 컷 변경으로 새로 생긴 문제도 다시 표시한다.

### 수정·저장·렌더링

- 텍스트, 시각, 스타일, 자막 표시 여부를 프로젝트에 저장한다. 스키마 버전을 올리고 기존 v1/v2 프로젝트는 자막 없는 상태로 읽는다. 원본 식별 및 기존 컷·VAD 설정을 보존한다.
- 자막 수정의 실행 취소·다시 실행을 제공한다. 텍스트 입력 중 키보드 실행 취소가 의도치 않게 컷을 바꾸지 않게 한다.
- 컷·자막·스타일·선택 트랙이 바뀌면 이전 렌더 결과를 최신 상태로 표시하지 않는다. 저장 완료와 렌더 완료는 별개다.
- UTF-8 SRT는 텍스트와 편집 시간축을 내보낸다. SRT가 자막의 디자인까지 보존한다고 표시하지 않는다. 디자인 검증은 스타일이 실제 프레임에 합성된 MP4를 사용한다.
- 사용자 문구는 일반 텍스트로 다룬다. ASS 태그, HTML, 파일 경로, 셸 문자열로 해석하지 않는다. 출력 포맷의 예약 문자는 이스케이프한다.
- 자막 렌더러나 한글 폰트가 없으면 설명과 복구 경로를 표시한다. 자막이 빠진 영상을 자막 포함 출력 성공으로 처리하지 않는다.

### 효과음

첫 범위는 로컬 효과음 파일 한 종류의 클립 배치·이동·길이 조절·음량 변경·음소거다. 자동 효과음 추천은 이 편집 동작을 제안하는 형태로 연결한다.

배치는 원본 시각에 연결한다. 시작점이 삭제된 클립은 출력에서 제외되며 원본 컷을 복원하면 다시 나타난다. 삭제 구간에서 시작한 효과음을 가장 가까운 발화에 임의로 옮기지 않는다. 시작점이 유지된 클립은 변환된 시각에서 재생하고 파일 길이·사용자 길이·영상 끝 중 가장 짧은 지점에서 끝낸다. 이 계약을 UI 도움말과 테스트에 동일하게 적용한다.

프로젝트에는 음원 식별 정보와 편집값을 저장한다. 음원이 이동하면 재연결을 제공하고 다른 파일을 조용히 대입하지 않는다. 테스트는 직접 만든 비프·짧은 음원을 사용한다.

## 3. 정답 자료와 품질 목표

수치는 검증 전 초기 목표다. 결과를 본 뒤 같은 실행의 기준을 완화해 통과 처리하지 않는다.

| 자료 | 구성 및 독립 정답 | 용도 |
| --- | --- | --- |
| TR01 | 짧은 한국어 TTS와 직접 작성한 대본, 앞·중간·끝 무음 | 실제 로컬 모델·시각·빈 구간·오프라인 경로 재현. 실제 사람 정확도의 대체 자료가 아님 |
| TR02 | TR01의 우측 단독·반대 위상·44.1/48kHz·시작 PTS 오프셋·VFR 파생본 | 채널 선택, 디코딩, 원본 시각 보존 |
| TR03 | 기존 R01~R03에서 고른 비공개 한국어 구간 | 엔진·모델·설정 조정 전용 |
| TR04 | 기존 R04~R09에서 고른 6개 이상 평가 구간, 합계 30분 이상 | 사람이 먼저 작성한 전사, 단어·음절 시각, 전문 용어·숫자·부정 표현 정답 |
| CR01 | 위의 고정 시간축 예시, 한글·영문·숫자·줄바꿈·예약 문자가 있는 자막 | 매핑·이스케이프·저장·실제 합성 |
| FR01 | 정확한 시작 샘플·길이·진폭을 아는 비프와 영상 플래시 | 효과음 배치·믹싱·컷 매핑 |

TR04는 모델이나 설정 선택에 사용하지 않는다. 애매한 구간은 별도로 남기며 분모·제외 이유를 보고한다. 일반 발화, 작은 목소리, 주변 소음, 전문 용어를 모두 포함하고 조건별 결과도 제시한다.

- 전사 정확도: CER = `(문자 대치 + 삭제 + 삽입) / 정답 문자 수`. NFC 정규화 후 공백·일반 문장부호를 제외하되 숫자·단위·부정어·전문 용어는 보존한다. 원문 점수와 정규화 규칙을 함께 보관한다. 정답이 비어 있으면 CER는 `N/A`이며 허위 자막 수를 따로 센다.
- 초기 전사 목표: 조용한 한국어 구간 CER ≤10%, 작은 목소리·소음 구간 CER ≤20%. 모든 원본을 수동 교정 없이 정확히 전사한다고 약속하지 않는다.
- 자막 시각: 검토 완료된 자막의 시작·끝이 사람 라벨 기준 각각 200ms 이내인 비율 ≥95%. 모든 500ms 초과 오차는 개별 기록·수정한다. 이 STT 허용치는 프레임 단위 컷 매핑 오차의 허용치를 늘리지 않는다.
- 최종 교정: 사실·수치·단위·고유명사·부정 의미가 바뀐 미해결 오류 0건. AI가 더 자연스럽게 썼다는 이유만으로 통과하지 않는다.
- 효율: 같은 품질의 SRT와 자막 포함 MP4를 완성하는 데 든 사용자 작업 시간의 영상별 절감률 중앙값 ≥30%. 무음 편집만의 Q04 ≥50% 목표와 섞지 않는다. 자동 처리 대기는 따로 기록한다.
- 출력: 자막 시간 변환은 독립 정답과 출력 1프레임 이내로 일치. SRT 반올림 오차는 1ms 이내. 누락·중복·깨진 한글·잘못된 최신 결과 표시 0건.

모델·엔진·플랫폼별 전사 속도와 앱+모델 자식 프로세스 합산 메모리를 10분·60분 자료에서 3회씩 측정한다. 전사 모델의 자원 사용을 기존 무음 분석 성능으로 합산하거나 제외해 유리하게 보고하지 않는다. 전사 초기 목표는 처리 시간 ≤영상 길이, 합산 RSS ≤4GiB이며 UI 조작 p95 ≤200ms·취소 후 재시도 가능 ≤5초를 유지한다.

## 4. 로컬 전사 테스트

P0/P1 모두 해당 기능의 지원 완료 전 필수다. P0는 상태·원본·데이터 정확성, P1은 실제 품질·성능·사용 흐름이다.

| ID | 우선순위 | 실행 | 기대 결과와 증거 |
| --- | --- | --- | --- |
| T01 | P0 | 준비된 모델로 TR01을 실제 추론. 외부 네트워크 차단 | 원본→전사 완료, 한국어 문구와 유효한 시각 반환, 외부 요청 시도 0건. 모의 CLI 출력으로 대체 불가 |
| T02 | P1 | TR04·완전 무음·음악만 있는 구간 전사 | CER·시각 목표 및 조건별 결과. 무음 허위 자막 0건, 음악을 발화로 오인한 사례 별도 기록 |
| T03 | P0 | TR02와 복수 오디오 트랙에서 트랙·채널을 선택 | 선택 신호만 전사하며 원본 시각 유지. 우측 발화 누락·위상 상쇄·PTS 이중 보정 없음 |
| T04 | P0 | 준비·디코딩·추론 중 취소, 프로세스 종료, 디스크 오류 | 프로세스·임시 작업 정리, 기존 자막·컷 보존, 재시도. 실패한 일부 결과를 완료로 표시하지 않음 |
| T05 | P0 | 모델 없음·잘못된 해시·잘린 다운로드·실행 엔진 없음 | 원인 구분, 불완전 설치 사용 금지, 원본과 기존 모델 보존. 자동 클라우드 전환 없음 |
| T06 | P0 | 요청 후 파일·트랙·언어 변경, 오래된 응답 도착, 재전사 | 과거 결과가 새 프로젝트/수동 자막을 덮어쓰지 않음. 적용 대상·변경 상태 확인 |
| T07 | P1 | 모델·설정 고정, 짧은 자료 반복 및 10분·60분 실행 | 유효 구간·순서·범위 불변식, 모델 해시·설정·속도·메모리·취소 원시값 기록. 출력 문자열 완전 일치를 품질 근거로 삼지 않음 |

## 7. 실행 순서와 지원 판정

1. 시간축 고정 정답과 저장 계약부터 만든다. C01~C04를 코드 변경과 함께 검사한다.
2. 실제 전사 엔진·모델의 한국어 짧은 자료와 오프라인 실행을 확인한다. 준비·취소·복구 경로도 함께 검사한다.
3. SRT 출력과 실제 자막 렌더러를 연결하고 프레임을 열어 확인한다. C05~C06·C09~C10은 개발 서버와 패키지를 각각 실행한다.
4. 조정용 자료로 모델·초기값을 선택한 뒤 TR04의 품질·작업 시간·긴 영상 성능을 평가한다.
5. 사용자가 선택한 실제 AI 연결로 교정 작업을 실행한다. 모의 응답·로그인 확인·실제 작업 성공을 별도 상태로 기록한다.
6. 효과음은 FR01과 컷 매핑부터 구현하고 자막과 함께 실제 출력한 결과를 판정한다.

전사, 자막 편집·디자인, AI 교정, 효과음은 각각 필수 사례가 모두 통과한 기능만 지원 완료로 표시한다. 다른 기능의 실패나 미실행을 숨기지 않으며 전체 제품 완료 판정은 기존 G1~G4와 함께 검토한다. 미해결 발화·의미 손상, 잘못된 시간축, 저장 손실, 원본 변경, 거짓 성공은 해당 기능의 출시를 막는다.

실행마다 [결과 기록 양식](../testing/test-run-template.md)에 코드·모델·폰트·렌더러 버전, 입력/정답 해시, 출력 시각, CER의 분자·분모, 실제 프레임·청취 기록, 처리 시간·메모리·외부 호출·사용량을 남긴다. 비공개 전사 원문과 API 키는 저장소에 넣지 않는다.

## 8. 현재 확인한 기술 조건

계획 작성 시점의 2026-09-05 작업 환경에서 `whisper-cli`·`whisper-cpp`·`cmake`는 PATH에서 발견되지 않았다. 현재 FFmpeg에 `-h filter=subtitles`와 `-h filter=ass`를 실행하면 각각 `Unknown filter`가 나온다. 두 명령 모두 종료 코드는 0이었다. 따라서 엔진 준비나 자막 합성 지원을 종료 코드만으로 판정할 수 없다.

로컬 전사 후보는 [whisper.cpp 공식 프로젝트](https://github.com/ggml-org/whisper.cpp)다. JSON 시각 출력의 실제 계약은 도입할 고정 버전의 [CLI 소스](https://github.com/ggml-org/whisper.cpp/blob/b4938/examples/cli/cli.cpp)와 실행 결과로 확인한다. 이후 고정 소스로 빌드한 엔진과 해시를 확인한 small 모델을 Mac 패키지에 포함했다. 실제 사람 녹음의 한국어 품질은 아직 검증하지 않았다.

FFmpeg `subtitles` 경로를 선택한다면 [공식 필터 문서](https://ffmpeg.org/ffmpeg-filters.html#subtitles-1)의 libass 지원 조건을 만족하는 실행 파일과 한글 폰트가 필요하다. 실제 구현에서는 `@napi-rs/canvas`와 번들 Noto Sans KR로 PNG를 만들고 기존 FFmpeg의 `overlay`로 합성하는 경로를 선택했다. 전역 FFmpeg를 교체하지 않았으며 같은 실제 프레임·시간축 테스트를 적용했다. 렌더러·폰트 버전·누락/취소·두 앱의 증거는 후속 결과 기록에 있다.
