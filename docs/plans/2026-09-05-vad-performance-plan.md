# 긴 영상 말소리 보호 성능 검증

현재 앱의 선택형 로컬 VAD를 켜고 1080p30 H.264/AAC 48kHz 10분·60분을 Chrome와 Mac 패키지에서 각각 3회 측정한다. 먼저 60초로 시험 도구를 점검한다. 생성한 한국어 Eddy TTS를 반복한 자료의 음량을 낮춰 임계값만으로는 전 구간이 후보가 되고 실제 VAD 추론으로 유지 구간이 생기는 경로를 사용한다. 합성 자료 통과는 실제 녹음의 발음 보존·CER·편집 시간 절감 근거가 아니다.

- 파일 선택 직전부터 업로드/네이티브 검사·해시·파형·프레임 시간표·VAD·화면 컷 준비까지 측정한다. 목표는 입력 길이의 20% 이하다.
- 내보내기 클릭부터 실제 출력의 전체 디코딩 검증과 저장 버튼 표시까지 측정한다. 목표는 입력 길이 이하다. 최종 사용자 경로 복사 시간은 포함하지 않는다.
- Chrome+별도 로컬 서버 또는 Mac 앱과 각각의 모든 자식 프로세스 합산 RSS를 250ms마다 수집한다. 드라이버는 제외하고 표본 오류를 보존한다. 분석·조작·출력 각 단계의 최대치를 기록하며 초기 목표는 2GiB 이하다.
- 각 실행에서 복원/실행 취소 32회, 설정 변경 32회, 재생/정지 32회를 측정한다. Playwright 호출 직전부터 기대 상태 확인과 2회 화면 갱신까지의 시간으로 자동화 오버헤드도 포함한다. 각 조작 묶음 p95 ≤200ms를 비교하며 미디어 처리 3회로 p95를 계산하지 않는다.
- 첫 실행 후 실제 VAD 추론 도중 취소한다. 취소 문구의 DOM 갱신 ≤300ms·서버 취소 완료와 UI 재시도 가능 ≤5초를 검사하고, 저장한 전체 프로젝트가 유지되는지 비교한다. 다음 측정 실행의 완료를 취소 후 재시도 완료 근거로 삼는다. 1회짜리 도구 점검에서는 취소를 생략한다.
- 분석이 실제 Silero 모델을 사용했는지, 디코딩 표본 수·구간 유효성·출력 길이·전체 디코딩 여부·반복 결과의 구간 일치·원본 해시를 확인한다. 기대 음량 이하라는 수치와 VAD 구간 생성은 추론 경로 확인이며 발음 품질의 독립 정답이 아니다.

각 조건의 첫 실행은 새 앱 프로세스이고 이후 두 번은 같은 앱이다. OS 파일 캐시를 비우지 않으므로 cold-cache로 표현하지 않는다. 사용자 앱을 종료하거나 시스템 전체 캐시·네트워크 설정을 변경하지 않는다. 다른 미디어 시험·빌드를 동시에 실행하지 않고 전원·칩·메모리·도구·앱/모델/자료 해시를 남긴다.

이번에는 VAD를 포함한 무음 편집을 측정한다. 1,000컷 임계값 단독의 최신 앱 측정, 긴 영상의 자막·효과음 동시 합성, OS cold-cache는 별도 조건으로 남긴다. 목표 실패는 숨기거나 기준을 완화하지 않고 원인·최적화 필요성을 기록한다.
