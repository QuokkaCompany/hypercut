# 로컬 전사 준비 상태와 복구 안내

2026-09-06. 기존 전사 T05의 ‘모델 없음·손상·지원하지 않는 실행 환경을 구별한다’는 계약을 보완한다. 현재 `transcriptionStatus`는 모든 실패를 하나의 준비 안내로 반환한다. 크기와 버전 검사에 통과한 상태는 실제 모델 해시 검사까지 끝났다는 뜻이 아니며, 이 구분을 유지한다.

## 변경 범위

- 엔진 파일 없음, 일반 파일이 아님, 읽기/실행 권한 문제, 모델 없음·파일 형식·길이 문제, 지원하지 않는 엔진 버전, 실행 실패, 상태 확인 시간 초과를 원인 코드와 한국어 안내로 구분한다.
- OS 오류나 엔진의 표준 오류를 그대로 화면에 출력하지 않는다. 사용자는 필요한 모델 준비, 권한 확인 또는 호환되는 앱 재설치와 ‘다시 확인’으로 복구할 수 있다. 개발용 설치 명령은 문서에 둔다.
- 정상 응답의 `ready`, `model`, `engine`, `local`, `integrity` 계약은 유지한다. 상태 확인은 파일 종류·접근 가능 여부·길이·버전을 확인하며, 전체 모델 SHA-256은 실제 전사 시작 전에 확인한다. 모델을 읽을 수 없거나 불완전하면 전사 가능 상태로 표시하지 않는다.
- 버전은 고정 엔진의 `1.9.3` 및 현재 패키지의 `1.9.3-dev`를 허용한다. 실제 CLI가 반환하는 `whisper.cpp version: ` 접두사를 포함한 형식도 검사한다. `1.9.30`처럼 문자열 일부만 같은 버전은 지원하지 않는다.
- 요청 취소는 오류 상태 응답으로 변환하지 않고 취소로 전파한다. 엔진 상태 확인의 10초 제한과 종료 정리를 유지하며, 실패 때문에 외부 전사나 모델 다운로드를 자동 시작하지 않는다.
- 기존 영상·모델·자막·컷은 상태 조회로 변경하지 않는다. 자막 직접 수정과 저장은 로컬 모델 준비 실패와 독립적으로 사용할 수 있어야 한다.

## 검증

실제 파일 시스템과 시험 소유의 작은 엔진 프로세스로 누락·권한·잘못된 버전·실행 실패·시간 초과·취소를 재현한다. 모델 크기 검사는 sparse 파일로 수행하고 이 파일을 정상 모델 또는 실제 추론 증거로 취급하지 않는다. 원본 앱의 모델·엔진은 변경하지 않는다.

| 사례 | 확인할 동작 |
| --- | --- |
| R01 | 엔진 누락과 모델 누락을 구분하고 불필요한 엔진 실행 없음 |
| R02 | 파일이 아닌 경로, 모델 길이 오류, 읽기/실행 권한 오류를 구분하고 파일 보존 |
| R03 | 지원 버전·미지원 버전·접두사가 같은 다른 버전을 판정 |
| R04 | 실제 프로세스 실패의 안내에 경로·표준 오류가 노출되지 않음 |
| R05 | 실제 10초 시간 초과와 사용자 취소 뒤 상태 확인 프로세스 종료 |
| R06 | 정상 상태 확인을 모델 해시 검증 완료로 표시하지 않으며, 같은 길이의 손상 모델은 전사 전 거부 |
| R07 | 인증된 상태 API가 같은 원인 정보를 반환하며 인증 없는 요청 거부 |
| R08 | 브라우저·Mac에서 누락 안내→복구→다시 확인, 기존 자막·프로젝트 보존, 실제 로컬 전사 재시도 |

먼저 현재 동작의 실패 근거를 남기고 보완 후 같은 검사를 실행한다. 이어서 기존 실제 전사 테스트와 두 앱의 복구 흐름을 확인한다. 상태 검사 모의 엔진을 실제 Whisper 추론이나 한국어 정확도 근거로 집계하지 않는다.

진행 중인 `86a5c4d`의 60분 warm 3회는 제품·번들·패키지를 바꾸기 전에 완료·감사한다. 그동안에는 이 계획과 앱이 읽지 않는 테스트 준비만 진행한다. 전사 준비 상태를 보완하면 후보가 바뀌므로, 나머지 전체 성능 행렬은 그 이후에 실행한다. 현재 측정값은 원래 후보의 근거로 보존한다.
