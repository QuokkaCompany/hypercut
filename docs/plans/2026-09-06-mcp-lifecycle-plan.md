# MCP 공유 요청과 늦은 응답 검증

2026-09-06. 기존 A05/A08과 [MCP 계약](2026-09-06-chatgpt-mcp-plan.md)의 미실행 경합을 실제 Chrome·Mac 앱에서 확인한다. 인증된 모델 요청이나 새 연결 방식을 추가하는 작업이 아니다.

| 사례 | 지연할 응답과 사용자 동작 | 통과 조건 |
| --- | --- | --- |
| L01 | 공유 생성 A 응답을 보류한 동안 요청을 바꾸고 공유 B 생성 | 뒤늦은 A는 해제되고 B의 ID·내용·준비 상태가 보존됨 |
| L02 | 공유 생성 응답 보류 → AI 창 닫기 → 다른 원본·프로젝트 열기 → 새 공유 | 이전 공유 해제, 새 원본·설정·공유 보존, 이전 내용 표시 없음 |
| L03 | 제안이 포함된 상태 조회 응답 보류 → 요청 변경 → 새 공유 | 이전 제안은 새 비교 화면에 나타나거나 적용되지 않음 |
| L04 | 설정 적용 전 상태 확인 보류 → 요청 변경 → 새 공유 생성도 보류 → 이전 확인 응답 도착 | 이전 요청의 오류·완료가 새 공유의 로딩·오류·편집 상태를 덮어쓰지 않음 |
| L05 | 공유 생성 응답 보류 → 다른 AI 연결 방식 선택 → 응답 도착 | 이전 공유 해제, 선택한 연결 방식 유지, MCP 화면 재등장 없음 |
| L06 | 현재 공유의 적용 전 조회에 503 응답 → 오류 확인 → 적용하지 않고 검토 완료 | 현재 요청의 오류는 표시되고 재시도 가능, 설정 보존, 실제 거절 결과 기록 |

서버 작업을 실제 수행한 후 응답 전달만 Playwright로 보류한다. 공유 생성·읽기·해제는 앱의 실제 HTTP 경로를 사용한다. 이 시험은 앞서 확인한 stdio 프로토콜을 다시 검사한 것으로 집계하지 않는다. 각 보류 응답의 시작·해제·전달을 기록하고 생성 지연은 앱의 5초 제한 안에서 끝낸다. 시간 초과한 생성의 90초 임대 만료는 기존 계약 검사와 구분한다.

L06은 실제 상태 조회 뒤 시험에서 503 응답을 주입하는 대조 사례다. 과거 응답을 무시하도록 바꾸면서 현재 요청의 실패까지 감추지 않는지 확인한다. 실행 전 브라우저 번들·관련 소스와 Mac 패키지 내부의 파일 해시가 일치하는지도 검사한다.

합성 원본 두 개와 서로 다른 프로젝트 설정으로 새 대상의 보존을 확인한다. 모든 사례에서 실제 설정 값·새 공유 문맥·이전 공유 접근 거부를 검사하고 최종 프로젝트 파일을 저장해 전체 필드를 비교한다. Mac 파일 선택·저장 창의 반환 경로는 시험이 지정한다. 실제 OS 대화상자 수동 검사의 대체가 아니다.

문제가 발견되면 실패 결과와 소스 해시를 남기고 해당 상태 전이만 수정한다. 수정 후 두 앱의 모든 L 사례와 기존 MCP 전체 흐름을 재검사한다. 제품·패키지를 고정한 다음 장시간 미디어 성능 검사를 시작하며, 성능 측정 중에는 앱 코드를 바꾸지 않는다.
