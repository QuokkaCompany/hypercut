# AI 효과음 제안 계약과 검증 계획

기준: `6c8026b`의 로컬 효과음 편집. 기존 [FX04 계획](2026-09-05-caption-effects-validation-plan.md)을 실행한다. 실제 음원 청취 능력이나 공급자 인증 성공을 모의 제안으로 대체하지 않는다.

## 전달 범위

사용자가 음원(최대 8개), 수정할 기존 클립(32개), 참고 자막(선택 사항, 20개·4,000자)을 명시적으로 선택한다. 음원은 별칭·사용자가 입력한 설명·길이, 클립은 별칭과 원본 시각/음원 시작/길이/음량/음소거만 전달한다. 영상 길이와 전체 유지 구간(최대 2,000개)을 포함해 원본/편집 시각을 구분한다. 파일명·SHA-256·경로·영상·음성은 보내지 않는다. 음원 설명과 자막은 모델이 실행할 명령이 아닌 참고 데이터다.

## 제안 및 적용

- 요청별 UUID와 최대 20개의 추가·수정·삭제 제안을 사용한다. 엄격한 JSON 스키마와 별도 런타임 검증을 함께 적용한다.
- 수정/삭제는 선택한 기존 클립만 가능하다. 원래 값이 요청과 정확히 일치해야 한다. 새 클립은 요청에 예약한 새 ID와 선택한 음원만 사용한다.
- 중복 ID/타깃, 다른 요청, 알 수 없는 음원, 범위 밖 시각·음량, 누락/추가 필드, 잘못된 before/after 조합은 응답 전체를 거부한다.
- 모든 제안은 미선택으로 시작한다. 원본/편집 예상 시각·음원 시작·길이·음량·음소거·삭제 여부를 비교하고 선택한 제안만 한 번의 실행 취소 단위로 적용한다. 프레임 정렬된 최종 결과는 정확한 미리보기로 확인한다.
- 시작점이 삭제 구간에 있거나 효과음 꼬리가 영상 끝을 넘으면 실제 출력되는 범위를 표시한다. 자동으로 가까운 발화로 이동하지 않는다.
- 적용 시 현재 영상·컷·효과음·참고 자막 스냅샷을 다시 검증한다. 변경된 상태에는 새 제안이 필요하다. 새 클립의 실제 ID는 요청 UUID에서 결정하므로 중복 적용으로 같은 클립을 복제하지 않는다.
- 기존 선택형 AI 연결/수동 JSON 경로를 재사용한다. 설정·자막·효과음은 하나의 활성 요청을 공유하고 요청별 취소·중복 방지·연결 해제·오래된 응답 폐기를 유지한다. 자동 재시도나 공급자 전환을 추가하지 않는다.

## 시험

1. 도메인: 전달 범위, 독립 before/after 정답, 추가/수정/삭제 선택 적용, 원본 불변, undo/redo에서 쓸 원래 상태, 중복·범위·스냅샷 거부.
2. 공급자: 세 HTTP 공급자와 실제 모의 Claude CLI의 스키마/프롬프트/모델/사용량 계약, 오류와 취소. 실제 인증된 호출은 별도 미실행으로 기록.
3. API: 요청 전 취소, 중복 요청, 다른 작업과 동시 실행 차단, 이전 ID 취소가 새 작업을 중단하지 않음, 연결 해제 후 늦은 응답 폐기.
4. 두 앱: 명시적 선택→수동 제안 가져오기→비교/부분 적용→실행 취소/재실행→프로젝트 저장→자막·컷·효과음이 포함된 실제 MP4의 시각·음량 검사. 삭제 제안 미선택과 선택하지 않은 음원/자막이 보존되는지도 검사.
5. 회귀: 기존 설정·자막 교정, 수동 효과음 편집, 미디어/자막 출력. 최종 빌드와 Mac 패키지를 실행한다.

위 단계 통과는 계약과 제품 동작의 근거다. 실제 모델의 제안 품질, 실제 사용 음원의 자연스러움, 긴 프로젝트 성능과 사람 작업 시간은 남은 품질 평가에서 확인한다.
