# HyperCut MVP test plan

Created: 2026-09-05. Clarified: 2026-09-06 (AI cost checks, execution order, and pre-run conditions). This document specifies tests; later execution evidence lives in the [testing index](../testing/README.md). It does not establish that all gates have passed.

Contracts: [validation targets](2026-09-05-validation-plan.md), [product design](../superpowers/specs/2026-09-05-hypercut-silence-first-design.md), [plan overview](README.md).

## 1. Execution rules and priorities

MVP P0 covers cut correctness, speech, synchronization, source protection, and edit preservation. MVP P1 covers supported formats, complete workflows, usability, and performance. Both are required for the first fully validated MVP. AI P0/P1 applies separately to each connection before enabling that integration as validated.

Decode the actual MP4 output. File existence and FFmpeg exit code zero are insufficient. Expected values must come from fixed examples, independent reference calculations, marker detectors, or human labels, never the product's own interval implementation or log parser. Mock UI checks cover faults and state transitions; separate E2E checks use real media and filesystems.

Node's test runner and Playwright currently implement automation, but case IDs are independent of tools. The 22 transcription/caption/effect cases are in the [T/C/FX plan](2026-09-05-caption-effects-validation-plan.md), separately from the 39 MVP and eight AI cases below.

## 2. Fixture specification

These IDs specify required data, not a claim that every file already exists.

| ID | Construction | Purpose |
| --- | --- | --- |
| F01 | 12-second, 48 kHz PCM with normal-level signal and two-second silence blocks | Exact sample boundaries and interval arithmetic |
| F02 | Constant absolute PCM values immediately below, equal to, and above threshold | Inclusive comparison, both signs, representable floating-point/quantization boundaries |
| F03 | Minimum duration minus/equal/plus one sample, with isolated noise | Duration boundary and continuity reset |
| F04 | Leading/trailing silence, all silence, no silence, very short input | File edges, empty output, overlapping padding |
| F05 | Stereo speech on left/right only and opposite-phase channels | Preserve either channel; expose destructive downmixing |
| F06 | MP4/MOV with separate microphone and music tracks | Selected analysis/output track |
| F07 | Marked 24/25/29.97/30/60 fps and VFR video with frame schedule | Inward snapping and source-to-output mapping |
| F08 | Synchronized flashes/beeps at beginning, middle, end, and many cuts | Per-cut sync and cumulative drift |
| F09 | H.264/AAC MP4/MOV derivatives of F01/F07/F08 at 44.1/48 kHz | Actual codec boundaries and delay |
| F10 | No audio, unreadable input, damaged headers, unsupported format | Import failures and recovery |
| F11 | Standard 10-/60-minute videos and separate 60-minute/1,000-cut stress input | End-to-end timing, memory, and long-run sync |
| R01–R03 | Three private Korean recordings | Tune initial settings and help text only |
| R04–R09 | At least six non-overlapping real Korean recordings | Independent speech/pause labels, quality, and editing time |

Each manifest includes ID, version, generation rules/seed, SHA-256, codecs/container, tracks/channels, sample rate, duration, frame schedule, settings, expected intervals, and oracle provenance. Changes to expected values require a reviewable reason. PCM/WAV engine fixtures do not imply UI support for those formats. Resolve any F02/FFmpeg mismatch against the product contract before passing G1.

## 3. Test layers

| Layer | Real dependencies | When |
| --- | --- | --- |
| Domain | Numeric fixtures and independent expectations | Relevant domain changes |
| Media integration | Pinned FFmpeg/ffprobe and small actual media | Media/timeline changes |
| Browser and native E2E | Actual applications, processing, upload/download or native open/save dialogs | Completed feature groups and release candidates |
| Failure/recovery | Isolated files and controlled process/write/stale-response faults | Job/save changes and release candidates |
| Human/performance | Real apps, labeled recordings, listening, timers | Usable candidate build |
| AI contract/connection | Mocks first, selected authenticated provider separately | Before validating each integration |

Keep small synthetic fixtures reproducible. Do not run long media or human evaluation for every unit change.

## 4. Silence and editing domain cases

| ID | Priority | Action | Expected evidence |
| --- | --- | --- | --- |
| D01 | MVP P0 | Analyze F02 below/equal/above values | Inclusive at-or-below comparison at sample precision |
| D02 | MVP P0 | F03 duration ±1 sample and exact duration | Below minimum rejected; equal/above accepted; at most one-sample error |
| D03 | MVP P0 | Insert a short above-threshold signal | Continuous silence timer resets; intervals are not arbitrarily joined |
| D04 | MVP P0 | Silence [10,12), post 0.15 s, pre 0.10 s | Before snapping, remove [10.15,11.90), exactly 1.75 s |
| D05 | MVP P0 | Leading/trailing silence and padding changes | No padding for nonexistent neighboring speech |
| D06 | MVP P0 | Remaining removal below/equal/above 100 ms | Reject below 100 ms both before and after snapping; no inverted interval |
| D07 | MVP P0 | Overlapping/duplicate/reversed/out-of-bounds candidates | Sort, merge, clamp valid data; reject corruption such as NaN/inversion; no double counting |
| D08 | MVP P0 | F05 single-channel and opposite-phase speech | Preserve whenever either channel exceeds threshold |
| D09 | MVP P0 | Select microphone/music tracks in F06 | Analyze selected track and retain its identity |
| D10 | MVP P0 | Put F07 boundaries between frames | Start snaps forward, end backward; kept content is not invaded |
| D11 | MVP P0 | Compute kept ranges and duration | Kept/removed ranges partition source, with ordered output mapping |
| D12 | MVP P0 | F04 all/no silence and short file | All-silent draft remains restorable; empty export blocked; no-silence gives zero cuts |
| D13 | MVP P1 | Repeat three times, then raise threshold | Identical intervals for identical inputs; raw low-level sample set cannot shrink |
| D14 | MVP P0 | Restore, undo, redo, save, reopen | Settings, intervals, and duration reproduce without lost edits |
| D15 | MVP P0 | Change settings during A and start B | Late A never overwrites B or appears current |

Use both fixed examples and invariants. Reimplementing the same algorithm inside a test is not an independent oracle. Byte-identical re-encoded MP4s are not the determinism criterion.

| M02 | MVP P0 | Compare markers around many cuts and first/middle/last | Meet per-marker and accumulated sync tolerance, documenting codec/frame delay |
| M03 | MVP P0 | 44.1/48 kHz, input PTS offset, VFR | Normalize start and preserve content positions/sync after cuts |
| M04 | MVP P1 | MP4/MOV × representative fps × mono/stereo | Import/analyze/export supported combinations; list untested combinations |

| M06 | MVP P0 | Compare fast draft, boundary preview, final output | Same kept ranges; seeking latency recorded separately |

| U02 | MVP P1 | Change threshold, select waveform/cuts, play/use keys | Settings and UI agree; response targets met |

| U04 | MVP P1 | Filenames with Korean, spaces, quotes, shell characters | Treat names as data, never commands |
| U05 | MVP P0 | Move source after save; reconnect wrong then correct file | Correct file reconnects; wrong media never receives old cuts |
| E01 | MVP P0 | Cancel analysis, preview, and export | Meet response/cleanup limits, stop child work, preserve state, allow retry |

Inject faults only into isolated temporary directories and processes. Do not fill a user's real drive or delete existing files. Mock write failures do not establish actual OS error behavior.

## 6. Human quality and time cases

| ID | Priority | Procedure | Pass criterion |
| --- | --- | --- | --- |
| Q01 | MVP P0 | Listen at least one second before/after every R04–R09 cut; widen questionable regions | Zero clipped words/syllables; classify soft speech, endings, breaths, intentional pauses |
| Q02 | MVP P1 | Intersect independent labels with removed ranges | ≥99% removal precision and ≥90% eligible-pause removal, also per recording |
| Q03 | MVP P1 | Review and restore poor cuts | Quality-driven restorations ≤5%; record all restorations, reasons, and time |
| Q04 | MVP P1 | Balanced-order manual/automatic paired editing | Speech quality passes and median active-time savings ≥50%; report elapsed time separately |
| Q05 | MVP P1 | Low-pause, music-mixed, and quiet-speech material | Include ineffective conditions; help and track selection explain real limits |

For uncertain pronunciation, reverse listening order and compare again. Leave unresolved judgments unresolved. Matching transcription strings do not prove speech preservation. Play the entire result at least once to catch faults outside cut boundaries.

## 7. Optional AI cases

Planning did not perform external inference, authentication, upload, or billing. Later mock/CLI and installed-login checks are recorded separately in [CLI results](../testing/2026-09-05-claude-cli-results.md). Recheck provider support and account capabilities when running real integrations.

| ID | Priority | Scenario | Pass criterion |
| --- | --- | --- | --- |
| A01 | AI P0 | Disabled/disconnected AI or absent model server | Local editing/save/export continue; explain reconnect path |
| A02 | AI P1 | Natural-language settings request to selected local/API model | Only selected provider/model called; structured proposal; no fallback |
| A03 | AI P0 | Invalid JSON, out-of-range values, unknown actions, command instructions | Reject with error; no code execution or invalid edits |
| A04 | AI P0 | 401/403/429/5xx, timeout, cancellation | Distinguish causes, no unbounded retries, preserve edits |
| A05 | AI P0 | Change settings/project/provider before response | Old proposal never automatically applies to current state |
| A06 | AI P0 | Inspect provider switch, request, project, logs, exports | Intended data only; no unintended keys, subscription tokens, or original media |
| A07 | AI P1 | Real Ollama, direct API, supported ChatGPT/Claude connections | Independently verify authenticated work, selected tool/model, and usage per provider |
| A08 | AI P0 | Read-only tool call, duplicate request, disconnect | Reads do not edit; duplicate edits are not reapplied; revoked requests rejected |

Evaluate varied wording, mixed units, and incomplete requests against allowed settings and context, not exact prose. Real paid calls occur only in a test session selecting that provider, with usage recorded.

Cost checks are part of existing cases, not additional case counts: U01/A01 require zero paid calls for core editing; A02/A06 require zero inference on settings save/switch and exactly identified attempts on request; A04 checks retries/fallback and includes failed/canceled usage; A07 records a predeclared call/usage/cost ceiling and per-attempt billing evidence. Unknown billing is unknown. The operator enforces the test ceiling; no automatic cost-control UI is implied. Economic comparisons require a verified baseline.

For the subscription CLI, distinguish missing installation/options/login and API-only authentication. Do not fall back to another authentication path. Test settings save, login checking, and model success separately, including saving settings during a login check. Exercise actual subprocess stdin, UTF-8, timeout, size limits, cancellation, and shutdown using mocks before real inference. Shell characters remain data. Disable model file/shell/MCP tools and send only the request and four permitted settings. Real inference evidence must include model, valid proposal, before/after settings, and actual usage; mock tokens or login status do not satisfy A07.

## 8. Execution order and recording

1. Build F01–F05 and independent expectations; manually inspect sample references and record the environment.
2. Run D01–D12 and M01–M03 before expanding the editor around unresolved cut/sync failures.
3. Add D13–D15 and U/E as edit, save, and job state become available.
4. Exercise supported combinations and actual app E2E; fix short reproducible failures first.
5. Tune on R01–R03, freeze settings, then evaluate Q01–Q05 on R04–R09. Run P01/P02 separately with F11 and fixed hardware/cache conditions.
6. Run all MVP P0/P1 on the release candidate and record gate decisions in the [result template](../testing/test-run-template.md).
7. Run AI cases separately per connection. Unavailable authentication is BLOCKED with a reason, not merged into another provider's results.

Allowed statuses: `NOT_RUN`, `PASS`, `FAIL`, `BLOCKED`, `N/A`. N/A requires an explicit out-of-scope reason; unimplemented functionality is NOT_RUN or BLOCKED. Preserve expected/actual intervals, settings, decoded metadata, marker errors, source hashes, job events, and raw performance. Keep private media and credentials outside Git and redact sensitive identifiers from shared logs.

## 9. First execution batches

Before each batch, record run/operator/case IDs, application, supported and excluded conditions, code and executable package identity, model/runner/fixture/oracle/label versions and hashes, settings/track/VAD state, expected tolerance, evidence location, and stop conditions. Real AI additionally needs the selected connection and call ceiling.

| Order | Batch | Prerequisite | Evidence | Cases |
| --- | --- | --- | --- | --- |
| 1 | Threshold/duration/padding boundaries | F01–F05, independent oracle, fixed settings | Expected/actual intervals and minimal failing inputs | D01–D08, D11–D13 |
| 2 | Real short-video output | Batch 1, F06–F09, A/V markers | MP4, full decode, boundary marker errors, selected track | D09–D10, M01–M06 |
| 3 | Complete edit in both apps | Batch 2 and identified builds | Import/analyze/restore/undo/save/reopen/export, original hashes | D14, U01–U05 |
| 4 | Cancellation/errors/stale responses | Normal flow and isolated fault injection | Failure/retry evidence for cancellation, overwrite cancel, disk full, shutdown, project switch | D15, E01–E06 |
| 5 | Real Korean speech and time savings | User-designated R01–R09, independent labels, manual baseline | Per-recording quality, listening, restoration reasons, raw timing | Q01–Q05, S01–S07 |
| 6 | Final-candidate long use | Frozen product/package/runner, F11, hardware/power/cache | 10/60 minutes × both apps × three runs/cache condition, full output, cancel/retry | P01–P02 |
| 7 | Optional AI work | Mocks; actual connection/auth/call ceiling separately | Provider-specific proposals, selected apply, undo, recovery, usage | A01–A08 |

Missing real recordings do not block batches 1–4 or synthetic performance, but batch 5 stays NOT_RUN and cannot be replaced by TTS. Do not run batches 5 and 6 concurrently. Missing authentication does not prevent mock contract tests but leaves real connection verification outstanding.

If recommending VAD, compare threshold-only and threshold+VAD on tuning inputs first, then freeze the evaluation mode and settings. Do not tune on R04–R09. Both modes require zero damaged speech. S cases cover VAD boundaries, model failures, and offline behavior; Q cases establish human speech and pacing quality.

Browser upload/download and actual Mac open/save/replace dialogs require separate evidence. A mocked dialog return path does not prove OS interaction. Run a short analysis using bundled native runtime/model in the packaged application. The release report must gather batch statuses, failures/reproductions, human evaluation, final-candidate performance, and actually verified AI connections. Required failures or unresolved judgments prevent a completion claim.
