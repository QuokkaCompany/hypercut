# HyperCut MVP 테스트 계획

작성일: 2026-09-05
계획 보완일: 2026-09-06 — AI 비용 시험과 품질·성능 자료의 실행 순서를 명확히 했다. 새 테스트 실행 결과는 아니다.
상태: 테스트 명세. 계획 작성 시에는 실행 전이었으며, 이후 구현·실행 현황은 [검증 현황](../testing/README.md)에 별도로 기록했다. 이 계획 자체가 전체 통과를 의미하지 않는다.

## 1. 실행 원칙과 우선순위

- MVP P0는 컷 정확성·발화·싱크·원본 및 작업 보존에 관한 필수 테스트다.
- MVP P1은 지원 형식·전체 사용자 흐름·실사용성과 성능에 관한 필수 테스트다. 첫 정식 MVP 완료 전 P0와 P1을 모두 통과해야 한다.
- AI P0/P1은 후속 AI 기능을 활성화하기 전에 해당 연결별로 실행한다. MVP 미구현 기능의 테스트를 통과 또는 묵시적 적용 불가로 처리하지 않는다.
- 실제 출력 MP4를 디코딩하고 검증한다. FFmpeg 종료 코드 0이나 파일 존재만으로 성공 처리하지 않는다.
- 테스트가 제품의 구간 계산 함수나 로그 파서를 호출해 기대값을 만들면 안 된다. 고정된 수치 예시, 별도 참조 계산, 독립 표식 검출과 사람의 라벨을 사용한다.
- UI 모의 테스트는 오류·상태 전환을 빠르게 검사하는 데 사용하고, 실제 미디어 작업과 파일 시스템을 쓰는 E2E를 별도로 둔다.
- 현재 자동 검증은 Node test runner와 Playwright를 사용한다. 아래 사례 ID와 판정 기준은 도구와 무관하게 유지한다.
- 전사·자막·효과음의 T/C/FX 22개 사례는 [후속 계획](2026-09-05-caption-effects-validation-plan.md)에 정의한다. 아래 MVP 39개·AI 8개와 구분해 실행·집계한다.

## 2. 테스트 데이터 제작 명세

아래 ID는 제작할 자료를 정의한 것이다. 현재 디스크에 존재하는 파일 목록이 아니다.

| 자료 ID | 구성 | 정답 또는 용도 |
| --- | --- | --- |
| F01 | 48 kHz PCM, 길이 12초, 정상 음량과 2초 무음 블록 | 정확한 샘플 경계와 기본 구간 계산 |
| F02 | 일정한 절댓값의 PCM 블록, 임계값 바로 아래·동일·바로 위 | 부호에 무관한 비교, 부동소수/PCM 양자화 경계. 구현에서 표현 가능한 실제 수치로 고정 |
| F03 | 최소 지속 시간보다 1샘플 짧음·같음·1샘플 김, 순간 잡음 삽입 | 지속 시간 조건과 연속성 초기화 |
| F04 | 시작 무음, 끝 무음, 전부 무음, 무음 없음, 매우 짧은 파일 | 파일 경계, 빈 결과, 여유 시간의 겹침 |
| F05 | 스테레오 왼쪽/오른쪽만 발화, 두 채널 반대 위상 | 한쪽 발화 보존, 잘못된 다운믹스 상쇄 탐지 |
| F06 | 마이크와 배경 음악이 별도 트랙인 MP4·MOV | 선택 트랙 기준 분석 및 출력 트랙 선택 |
| F07 | 프레임 시간표와 발화 표식이 있는 24/25/29.97/30/60 fps 및 VFR 영상 | 프레임 정렬과 source→output 매핑 |
| F08 | 동시 플래시·비프가 있고 처음·중간·끝 및 다수 컷 주변에 표식이 있는 영상 | 컷별 시간축·싱크·누적 오차 |
| F09 | F01/F07/F08의 H.264/AAC MP4·MOV 파생본, 44.1/48 kHz | 실제 디코딩·인코딩 경계, 코덱 지연 처리 |
| F10 | 오디오 없음, 읽기 불가, 손상된 헤더, 지원하지 않는 형식 | 가져오기와 오류 경로 |
| F11 | 10분·60분 표준 영상, 별도 60분·1,000컷 스트레스 자료 | 전체 분석·내보내기·메모리·장시간 싱크 |
| R01~R03 | 비공개 실제 한국어 영상 3개 | 초기값·설정 도움말 조정 전용 |
| R04~R09 | 위 자료와 중복되지 않는 실제 한국어 영상 6개 이상 | 발화·쉼 라벨, 품질, 작업 시간 평가 |

각 fixture manifest에는 ID, 버전, 생성 규칙과 seed, SHA-256, 컨테이너/코덱, 채널과 트랙, 샘플레이트, 길이, 프레임 시간표, 기준 설정, 정답 구간·근거를 넣는다. 정답 파일 변경은 리뷰 가능한 변경으로 다루고 이유를 기록한다.

F01~F05의 PCM은 엔진 검증용이며 WAV/PCM이 UI의 지원 입력 형식이라는 뜻은 아니다. UI 호환성은 F06~F10의 명시된 제품 형식으로 검증한다. F02의 기준과 실제 FFmpeg 비교가 다르면 제품 계약과 일치하도록 해결하기 전 G1을 통과하지 않는다.

## 3. 테스트 계층과 실행 범위

| 계층 | 대상 | 실제 사용하는 것 | 실행 시점 |
| --- | --- | --- | --- |
| 단위/도메인 | 구간·여유·프레임 정렬·복원·직렬화·설정 검증 | 수치 fixture와 독립 정답 | 관련 코드 변경마다 |
| 미디어 통합 | 디코더, 분석 프로세스, 로그 처리, 실제 출력 | 고정 버전 FFmpeg/ffprobe, 작은 실제 미디어 | 미디어/시간축 코드 변경마다 |
| 데스크톱·브라우저 E2E | 파일 열기→분석→수정→저장→출력 | 실제 앱·미디어 작업·임시 파일 시스템. 브라우저 업로드/다운로드와 Mac 네이티브 파일 선택/저장을 각각 검사 | 기능 묶음 완성 및 출시 후보 |
| 장애/복구 | 취소, 프로세스 실패, 쓰기 실패, 오래된 응답 | 제어 가능한 장애 주입과 실제 상태 보존 | 작업/저장 코드 변경 및 출시 후보 |
| 실사용/성능 | 한국어 품질·시간 절감·긴 영상 | 실제 앱과 평가 영상, 사람 청취·시간 기록 | 사용 가능한 후보 빌드 |
| AI 계약/연결 | 공급자 선택, 결과 검증, 실제 인증 | 먼저 모의 공급자, 이후 선택한 실제 공급자 | AI 단계의 공급자별 활성화 전 |

작은 합성 fixture는 재생성 가능하게 유지한다. 긴 영상과 실제 영상 평가를 매 단위 테스트마다 실행하지 않는다.

| D12 | MVP P0 | F04의 전부 무음·무음 없음·짧은 파일 | 전부 무음은 복원 가능하되 빈 출력 불가. 무음 없음은 0건. 예외나 음수 길이 없음 |

| D14 | MVP P0 | 컷 복원→실행 취소→다시 실행→저장·열기 | 각 상태의 구간·설정·출력 길이가 재현됨. 이전 편집이 조용히 유실되지 않음 |
| D15 | MVP P0 | 분석 A 도중 설정 변경 후 분석 B 실행 | A의 늦은 결과가 B를 덮어쓰지 않음. 이전 설정 결과가 최신 결과로 표시되지 않음 |

정해진 기대값과 구간 불변식 검사는 함께 사용한다. 같은 구현을 테스트 안에 다시 작성해 맞추는 것으로 정답을 대체하지 않는다. 재인코딩된 MP4의 바이트 해시 일치를 결정성 기준으로 쓰지 않는다.

오류 주입은 테스트용 임시 디렉터리와 작업 프로세스에서 수행한다. 실제 사용자 드라이브를 채우거나 기존 파일을 삭제해 공간 부족을 재현하지 않는다. 모의 쓰기 실패만으로 실제 운영체제의 오류 처리까지 검증했다고 주장하지 않는다.

## 7. AI 선택 연결의 후속 테스트

계획 수립 단계에서는 외부 AI 호출, 인증, 업로드 또는 과금을 실행하지 않았다. 이후 모의 공급자·CLI 계약과 실제 설치/로그인 상태 검사를 추가했다. 인증된 모델 요청과 응답 품질 검증은 별도이며 현재 [AI 연결 실행 기록](../testing/2026-09-05-claude-cli-results.md)에 구분한다. 공급자의 가용성과 인증 방식은 실제 통합 시 공식 문서와 해당 계정으로 재확인한다.

| ID | 우선순위 | 시나리오 | 합격 기준 |
| --- | --- | --- | --- |
| A01 | AI P0 | AI 끄기·연결 끊기·모델 서버 없음 | 로컬 컷·저장·출력은 계속 동작. 원인과 재연결 경로 표시 |
| A02 | AI P1 | 선택한 로컬 공급자/모델과 API 공급자/모델에 자연어 설정 요청 | 실제 선택 대상만 호출, 구조화된 설정 제안 표시. 다른 공급자로 묵시적 대체 없음 |
| A03 | AI P0 | 잘못된 JSON·범위 밖 수치·알 수 없는 작업·명령 실행 지시 반환 | 결과 거부 또는 명시적 오류. 임의 코드/명령·잘못된 컷 적용 없음 |
| A04 | AI P0 | 401/403/429/5xx·시간 초과·사용자 취소 | 인증/권한/한도/서버/취소 구분, 무한 재시도 없음, 현재 편집 보존 |
| A05 | AI P0 | 요청 후 설정·프로젝트·공급자 변경, 과거 응답 도착 | 과거 제안이 현재 프로젝트/설정에 자동 적용되지 않음 |
| A06 | AI P0 | 공급자 전환, 요청/프로젝트/로그/내보내기 검사 | 연결 유형과 보낼 데이터가 일치. 키·구독 토큰·원본 영상이 의도치 않게 포함되지 않음 |
| A07 | AI P1 | 실제 Ollama, API 직접 호출, ChatGPT/Claude의 지원 연동 각각 확인 | 각 연결을 별개로 실제 작업 수행하고 인증·도구/모델·사용량 근거 기록. 모의 응답은 연결 성공 증거로 인정하지 않음 |
| A08 | AI P0 | 읽기만 요청된 외부 도구 호출, 중복 요청, 연결 해제 | 읽기는 편집을 변경하지 않음. 중복 편집 동작은 중복 적용되지 않고 해제 후 새 요청은 거부 |

자연어 평가에는 표현이 다른 요청, 단위가 섞인 요청, 불완전한 요청을 포함한다. 같은 설명 문구가 나오는지보다 허용된 설정 제안과 현재 작업 맥락에 맞는지 평가한다. 실제 유료 실행은 해당 공급자 사용을 선택한 테스트 세션에서만 진행하며 사용량을 기록한다.

비용 제약은 기존 사례 안에서 아래와 같이 검사한다. 별도 사례 수로 중복 집계하지 않는다.

| 연결 사례 | 입력·행동 | 기대 결과와 증거 |
| --- | --- | --- |
| U01, A01 | AI 미연결·외부 네트워크 차단 상태에서 컷 편집부터 출력까지 수행 | 유료 모델 요청 0회, 기본 작업 완료. 최초 도구·모델 준비의 다운로드는 별도 기록 |
| A02, A06 | 공급자 설정 저장·전환 후, AI 제안 요청을 한 번 실행 | 저장·전환 단계의 추론 요청 0회. 요청 단계에서 선택한 공급자만 호출하며 실제 시도 횟수 기록 |
| A04 | 공급자 오류·한도 초과·취소 주입 | 무한 재시도와 다른 유료 공급자로의 전환 없음. 실패·취소된 요청도 사용량 확인 대상에 포함 |
| A07 | 사전에 기록한 호출·사용량/비용 상한 안에서 실제 연결 실행 | 시도별 모델·사용량·실제 청구 근거 보관. 상한 도달 시 수행자가 시험 중단. 확인 못한 청구는 `확인 불가` |

자동 비용 차단 UI를 테스트했다고 해석하지 않는다. 상한은 시험 운영 규칙이다. 경제성 비교는 확인한 기존 비용·사용 빈도가 있을 때만 계산한다.

구독 CLI 연결에서는 A01~A08을 아래 조건으로 구체화한다. 별도 사례 수로 중복 집계하지 않는다.

- 설치 없음·필수 옵션 미지원·로그인 없음·API 인증만 있는 상태를 구분한다. 구독 연결에서 다른 인증 경로로 자동 전환하지 않는다.
- 설정 저장, 로그인 확인, 유효한 모델 응답 성공을 각각 검사한다. 설정 저장만으로 실제 연결 성공을 표시하지 않는다.
- 로그인 상태 확인 도중 설정을 저장해도 상태 확인이 끝나고 재확인·요청 버튼을 사용할 수 있어야 한다.
- 모의 응답뿐 아니라 실제 자식 프로세스의 표준 입력·UTF-8 응답·시간 초과·크기 제한·취소·앱 종료를 검사한다. 셸 특수문자는 명령으로 해석하지 않는다.
- 모델의 파일·셸·MCP 도구를 비활성화한다. 요청에 자동 첨부한 영상·음성·파일명·인증 정보가 없어야 한다. 사용자 요청문과 허용된 네 가지 설정만 전달한다.
- 실제 인증 실행에서는 선택한 모델, 유효한 제안, 적용 전후 설정, 사용량 근거를 기록한다. 모의 토큰 수나 설치/로그인 확인으로 이 항목을 통과 처리하지 않는다.

## 8. 실행 순서와 결과 기록

1. F01~F05와 독립 정답을 먼저 제작하고 기준 환경을 기록한다. 정답 샘플을 사람이 확인한다.
2. D01~D12, M01~M03으로 음량 기준과 실제 컷·싱크의 가능성을 검증한다. 실패를 해소하기 전에 편집 화면 확장을 우선하지 않는다.
3. 편집·저장·작업 상태를 구현하면서 D13~D15, U/E 사례를 추가한다.
4. 지원 미디어 조합과 실제 앱 E2E를 수행한다. 짧은 fixture로 재현되는 실패를 먼저 수정한다.
5. R01~R03으로 초기 설정을 조정하고, 이를 고정한 뒤 R04~R09에서 Q01~Q05의 품질·작업 시간을 평가한다. P01~P02는 F11의 별도 합성 자료와 고정한 장비·캐시 조건으로 측정한다. 사람의 편집 세션과 성능 작업을 동시에 실행하지 않는다.
6. 출시 후보에서 모든 MVP P0/P1을 실행하고 [결과 기록 양식](../testing/test-run-template.md)으로 게이트를 판정한다.
7. AI 기능은 연결별로 A 사례를 별도 실행한다. 인증할 수 없는 공급자는 차단 상태와 이유를 기록하고 다른 공급자 결과와 합산하지 않는다.

모든 사례 결과는 `NOT_RUN`, `PASS`, `FAIL`, `BLOCKED`, `N/A` 중 하나다. `N/A`는 명시된 지원 범위 밖일 때만 근거와 함께 사용한다. ‘아직 구현하지 않음’은 `NOT_RUN` 또는 `BLOCKED`이며 `N/A`가 아니다.

원시 증거에는 입력/정답/출력 구간, 설정, 실제 디코딩 정보, 표식 오차, 원본 해시, 작업 이벤트, 성능 측정값을 포함한다. 비공개 미디어와 인증 정보는 저장소에 포함하지 않는다. 테스트 실패 로그는 파일과 계정의 민감한 식별 정보를 가린 후 공유한다.
