# 긴 컷·자막 목록의 화면 요소 수 제한

2026-09-06. 세로 영역 자막 합성의 브라우저 60분 두 번째 실행은 출력 정확성을 보존했지만 RSS 2.045GiB로 실패했다. 현재 컷 1,000개와 자막 1,000개가 모두 DOM에 있다. 반복 화면 교체에 따른 비용을 줄이기 위해 큰 목록의 화면 요소 수를 제한하는 후보를 구현한다. 메모리 누수로 확정한 원인은 아니며 정식 재측정 전에는 메모리 개선 성공으로 표시하지 않는다.

## 접근과 보존할 동작

기존 메모화와 화면 밖 자막의 CSS 렌더 지연만으로 반복 메모리 목표를 달성하지 못했다. 인코더 추가 축소는 출력 속도와 비트스트림에 영향을 준다. 이번에는 200개 이상인 컷·자막 목록만 가상화한다. 작은 목록은 전체 항목을 그대로 표시한다. 모든 항목은 프로젝트 데이터에 남고 출력·저장·복원·AI 작업에 같은 전체 데이터를 사용한다.

TanStack Virtual 3.14.10의 동적 높이 측정·고유 ID 키·추가 렌더 범위를 사용한다. [공식 API 문서](https://tanstack.com/virtual/latest/docs/api/virtualizer)와 [동적 목록 예제](https://tanstack.com/virtual/latest/docs/framework/react/examples/dynamic)를 확인했다. 보이는 항목 주변을 여유 있게 렌더링하고 선택 항목과 키보드 포커스 항목도 유지한다. 추정 높이로 문구를 자르지 않으며 실제 줄바꿈 높이를 측정한다. 의존 버전은 고정한다.

- 스크롤과 목록 순서, 모든 문구·시각·복원 상태를 유지한다. 가상화는 목록의 일부만 데이터로 불러오는 페이지 제한이 아니다.
- 기존 Enter/Space 선택·복원 버튼을 유지한다. Tab/Shift+Tab은 다음/이전 논리 항목으로 이어지고, Home/End로 처음/마지막 버튼에 접근한다. 포커스 항목이 화면 밖으로 스크롤돼도 임의로 사라지지 않는다.
- 자막의 미적용 문구 보호·다음 검토 항목 이동·선택 항목 삭제·수정에 따른 정렬·실행 취소/다시 실행·전체 프로젝트 왕복을 확인한다.
- 목록 항목의 전체 개수와 위치를 접근성 속성으로 제공한다. ‘모든 항목의 DOM이 항상 있음’이라는 이전 구현 조건은 ‘모든 항목을 실제 조작과 저장으로 접근할 수 있음’으로 변경한다. 출력 및 사용자 기능 범위는 줄이지 않는다.
- 원본/편집본 시각, 렌더 코드·품질·임계값·최소 길이·여유 시간·원본 보존 기준은 변경하지 않는다.

## 검증 순서

1. 타입/빌드와 단위 테스트, Mac 패키징을 확인한다.
2. 두 앱에서 큰 컷·자막 목록의 처음/중간/마지막 이동, Tab 경계 양방향, Enter/Space, 긴 여러 줄 문구와 크기 변경, 선택/수정/실행 취소/프로젝트 교체를 확인한다. 결과 문구·시각과 전체 저장 프로젝트를 비교한다. 보이는 인접 항목의 빈 영역·겹침과 실제 화면을 확인한다.
3. 기존 작은 목록의 편집·출력·작업 잠금·프로젝트 경합 회귀를 수행한다. 목록 개수를 DOM 개수로 추정하던 긴 영상 러너는 실제 전체 개수 표시와 전체 프로젝트 비교를 사용하고 실제 클릭/입력과 출력 정답은 유지한다. 과거 실패 기록은 수정하지 않는다.
4. 두 앱의 60초 동시 합성·취소·재시도를 확인한 뒤 같은 60분 브라우저 반복을 수행한다. 메모리 2GiB·각 조작군 p95 200ms·출력 정확성·취소 기준은 유지한다. 첫 실패 시 다른 장시간 조건을 확대하지 않는다.

실제 한국어 품질·작업 시간 절감·인증 AI·캐시/OS 네트워크 차단은 별도 검증이다. 이 후보를 이유로 이미 실패한 측정의 RSS를 추정해서 빼거나 브라우저 기능을 끄지 않는다.
